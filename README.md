# 小胰宝工作台

简体中文

小胰宝是面向胰腺癌患者及照护者的 DSH Desktop 本机工作台。它帮助用户整理已确认的检查资料、记录治疗与日常照护、回顾指标变化，并把需要讨论的问题交给 DSH Desktop 原生 Agent 会话。界面以 `docs/xyb-workbench/prototype-v3.html` 为高精度参照，医疗内容用于资料整理和沟通，不替代医生诊断或治疗意见。

## 功能

- 病程一图秀：按时间轴查看资料、治疗安排和已确认指标；指标卡片可翻转查看最近记录，单张卡片的展开状态彼此独立。
- 首页日历：查看从今天起未来 14 天的待办，按日期添加、修改、完成或取消本机安排。
- 病情整理：导入本机报告、查看原件、解析并逐项核对候选字段；只有确认的数据才进入指标记录。
- 文档解析：随包提供公益 MinerU API Token，首次云端解析需确认；凭据失效时提示更换并尝试 Flash 免费解析，TXT/MD/CSV 使用本地解析。
- 指标趋势：按肿瘤标志物、血常规、肝功能、感染、代谢与营养等类别查看趋势。
- 临床试验：使用随包的本地试验快照检索，查看记录详情、收藏，或把具体条目交给 Agent 继续询问。
- 营养、心理支持与全程管理：记录体重、能量摄入、营养制剂、感受、症状、周期治疗及复查安排。
- 收藏与回顾：集中查看收藏的试验、重要 Agent 任务和生成的病情报告。
- 报告导出：支持 PDF、JPEG、HTML、Markdown 和 DOCX，文件写入本地资料目录的 `output/reports/`。
- 本机 SQLite：患者资料、设置、报告和业务记录保存在用户明确选择的本机资料文件夹中。

## DSH Desktop 工作台适配

工作台通过 `desktopWorkbenches.register` 注册业务面板，遵循 Desktop 原生导航与会话管理。业务区域默认位于左侧，约占 65%；右侧由 Desktop 保留唯一原生 Agent 会话。工作台不覆盖侧边栏、设置、模式切换或公共导航。新建项目时，工作台请求 Desktop 建立并打开原生会话；模式、模型、工具和权限由原生会话管理。

本仓库提供 `package.json` 中的 DSH 包元数据、`cordis.patch.yml`、服务端入口 `dsh/index.js` 与客户端入口 `lib/client.js`。安装到 Desktop 时使用 DSH Desktop 当前支持的本地插件安装方式；安装后应在 Desktop 中确认工作台版本、业务面板和原生会话均已加载。

## 数据与能力边界

- `assets/trials.db` 是随包提供的本地临床试验数据快照，供离线初始化检索；它不是患者数据，更新信息以数据快照自身元数据为准。
- 患者数据必须存入用户明确选择的资料目录。导入文件在本机处理，识别字段先作为候选内容展示，用户核对后才能写入病情记录。
- 临床试验搜索结果是查找线索，不代表符合入组条件；试验状态和入排标准应向研究中心核实。
- Agent 建议由 Desktop 原生会话处理；提示内容应限于当前页面已汇总的信息，工具和文件访问遵循 Desktop 当前会话权限。
- 指标趋势用于回顾已确认记录。日期、单位或检测方法不一致时需先核对；工作台不根据单次变化给出诊断结论。
- 报告文件保存在本机 `output/reports/`，并登记在“收藏与回顾”。当前 PDF 采用与 JPEG 报告相同的图像版面，以保证跨平台中文显示。

## 本地开发与检查

要求 Node.js `>=22.5`（`node:sqlite`）。

```bash
npm install
npm run check
npm run pack:check
```

`npm run check` 会检查 JavaScript 语法、客户端结构、SQLite/API 流程、离线临床检索和 schema 合约示例。`npm run pack:check` 检查 npm 包内容，不会发布包。

本地打包：

```bash
npm pack
```

生成的 `.tgz` 可通过 DSH Desktop 支持的本地插件安装入口安装。安装完成后确认版本号与当前包版本一致，选择或创建本机患者资料目录，再检查患者切换、主要 Tab、右侧原生会话和导出文件。

小胰宝社区使用 Codex 开发工作台的流程、依赖、Desktop 对接和常见问题见 [AGENTS.md](AGENTS.md) 与 [Workbench 开发部署指南](docs/WORKBENCH-DEVELOPMENT-WITH-CODEX.md)。
