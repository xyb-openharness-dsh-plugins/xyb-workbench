# 小胰宝工作台 · Agent 查询与结果回写设计

日期：2026-10-13 · 状态：设计约束，待用 DSH Desktop 的公开 API 验证。

## 1. 两条查询路径

临床试验页面提供两个并列动作。

| 动作 | 适用场景 | 执行者 | 输出 |
| --- | --- | --- | --- |
| 本机快速查询 | 已有明确关键词、疾病或登记号 | 工作台本机服务 → `unified-trial-mcp` | 可筛选的登记记录与来源日期 |
| 交给 Agent 深入查询 | 需要把已确认病情资料转成问题、比较多来源、解释证据缺口 | DSH 的受绑定 conversation → 小胰宝检索技能/MCP | 带来源的候选结论、待确认项与下一步问题 |

本机快速查询不经过模型。Agent 查询也应优先调用同一个本机统一检索工具；本机语料就绪时，不因为使用 Agent 而改走网络。在线来源只有用户启用后才可被 Agent 使用。

`universal-search` 是希望支持的技能类别名称，不应在实现中假设它已经注册。本机已核实的候选统一检索服务是 `unified_search_trials` / `unified-trial-mcp`。交付前必须实际核验：技能 ID、工具名、会话创建/恢复 API 与插件作用域。

## 2. 工作台到 Agent 的明确交接

### 2.1 页面建议入口与角色提示

每个一级页面提供「给我建议」入口。入口只汇总该页面已确认、可追溯的信息，生成可编辑的任务预览后再交给 Agent；默认不传原始全文、不传其他页面的自由文本，也不把“未记录”“待核对”转写为事实。

页面角色用于确定资料筛选、分析顺序和输出格式，不用于授权 Agent 作医学诊断或治疗决定。建议角色如下：

| 页面 | Agent 角色 | 主要输出 |
| --- | --- | --- |
| 看板 | 胰腺癌病程管家 | 当前变化、近期计划、复诊准备问题 |
| 病情整理 | 病历整理与就诊准备助手 | 资料缺口、核对顺序、就诊沟通清单 |
| 病情一图秀 | 病程时间线解读助手 | 时间节点、可补记录、供复诊回顾的问题 |
| 临床匹配 | 临床试验线索助手 | 检索线索、缺失条件、研究中心待确认项 |
| 营养管理 | 肿瘤营养记录助手 | 已记录趋势、待补评估、营养门诊沟通问题 |
| 心理支持 | 心理支持陪伴助手 | 用户选择共享的感受、支持资源与自我照护安排 |
| 全程管理 | 治疗与照护计划助手 | 治疗、症状、并发症和照护待办的整理建议 |

所有页面角色共用以下输出边界：清楚区分已确认事实、资料缺口和需由医疗团队确认的事项；给出资料整理、记录和沟通建议；不诊断、不预测预后、不建议自行调整治疗、药物或剂量。

点击「交给 Agent 深入查询」后，工作台先显示一个可编辑的范围预览：

1. 查询问题与选择的数据来源。
2. 将传入的已确认事实，例如疾病、治疗线数、关键基因或 IHC 项目；未确认、未检测和缺失项要原样保留。
3. 不传入的内容，例如心理记录、未选择的原始病历、其他患者资料。
4. 将使用的本机语料版本、来源覆盖日期和在线来源状态。

用户确认后，工作台通过 DSH 的受支持公开 API 创建或恢复**绑定到当前患者和当前任务**的小胰宝会话，并提交结构化任务。不能模拟键盘输入、操作宿主私有 DOM，也不能把任务发送到无关会话。

任务提示词应要求 Agent：

```text
使用小胰宝已启用的数据源查询临床试验。优先本机统一检索工具；仅在来源已启用时查询在线来源。
逐项保留登记号、来源、查询日期、数据截止日期和原始证据链接/字段。
把“已满足”“不符合”“无法判定”分开陈述；缺失字段不得当作满足条件。
结果是查询线索，不是入组建议、诊断或治疗建议。
```

## 3. Agent 到工作台的结果回写

Agent 的整段回答不能直接覆盖病情资料或匹配结论。会话完成后，工作台显示“候选结果”收件箱；用户可以逐条选择：保存试验、保存待补资料、保存查询备注，或忽略。

每条保存项须带有：

- 当前患者 ID、查询任务 ID、会话绑定 ID；
- 试验登记号或资料字段 ID；
- 来源名称、来源版本/覆盖日期、查询执行时间；
- 原始证据定位、Agent 摘要、用户确认时间；
- 状态：候选、已保存、已确认、已过期或已移除。

保存试验可进入“临床匹配 → 收藏”。保存待补资料可进入“病情整理 → 待核对”。只有用户明确确认的病历事实才能进入患者结构化档案；工作台不能把 Agent 文本当成新的基因结果、病理结果或治疗记录。

## 4. 失败与降级

无 Agent 配置、技能未注册、MCP 未就绪或会话接缝不可用时，“交给 Agent”入口显示具体原因，并保留本机快速查询。任一来源失败时，要显示来源自身失败信息；其他来源的结果继续可用。不能把空结果解释为“没有试验”。

## 5. 原型对应

v3 在临床匹配的二级“试验检索”中提供“交给 Agent 深入查询”的交接入口；它展示范围、任务提示和结果回写规则。当前 HTML 原型不创建真实 DSH 会话、不调用技能、不查询本机数据，也不写入真实患者资料。

## 6. 订阅查询与日报任务

“临床匹配 → 收藏”可创建订阅：用户输入关注靶点、试验名称或登记号，选择查询范围和时间表。服务端调度器按计划生成结构化提示词，并通过 DSH 公开 API 交给当前患者、当前订阅绑定的 Agent 会话。

每次任务必须保存：订阅 ID、患者 ID、触发时间、计划时间、提示词版本、所选输入节点、数据集版本、Agent 会话 ID、执行状态和输出目录。失败只记录任务失败原因；不得把失败或空结果解释成“无试验”。

提示词固定要求：优先本机数据；逐项保留登记号、来源、覆盖日期和证据；区分可对照、资料待补和研究中心确认项；不得输出入组、诊断或治疗结论。

任务的日报输出写入 `output/<timelineNodeId>/trial-query/`，并在收藏页按订阅查看。用户可打开输出、保存候选线索或忽略；任何结果都不能自动覆盖患者档案。
