# 小胰宝工作台 · 全程管理与营养管理规格

日期：2026-10-13 · 状态：**设计建议稿，供用户讨论**。

上级文档：[SPEC-v0.4.md](./SPEC-v0.4.md)。本文定义两个一级 Tab：**营养管理**（新提升为一级）与**全程管理**（原「照护管理」更名后收窄）。

---

## 1. 导航变更说明

### 1.1 变更内容

| 原（v0.4） | 现（本稿） | 理由 |
|---|---|---|
| 照护管理（一级）含 6 项 | **全程管理**（一级）含 4 项 | 更名 + 收窄 |
| 营养管理在照护管理下 | **营养管理**（一级） | 用户要求：独立且与临床匹配同级 |
| 心理支持在照护管理下 | **心理支持**（一级） | 同上 |

一级 Tab 从 5 个变为 **7 个**：

```text
1 看板 | 2 病情整理 | 3 病情一图秀 | 4 临床匹配 | 5 营养管理 | 6 心理支持 | 7 全程管理
```

### 1.2 为什么营养与心理值得升为一级

不只是「用户要求」，也有内在逻辑：

| 模块 | 独立性 |
|---|---|
| **营养管理** | 胰腺癌患者营养不良发生率极高，且是**独立于抗肿瘤治疗**的干预线（胰酶替代、营养支持）。它有自己的评估（BMI/能量/PG-SGA）与随访节奏，塞在照护管理里会被埋没 |
| **心理支持** | 直接关系患者与家属的生存质量，且**涉及危机干预与临终议题**，需要足够的界面权重保证可发现性。放在二级会让最需要的人找不到 |

而留在「全程管理」下的 4 项（毒性、并发症、带管、血管通路）有共同点：**都是围绕具体治疗与器械的操作性管理**，属于临床随访范畴。

### 1.3 全程管理收窄后的定义

```text
全程管理
├─ 毒性管理      CIPN、皮疹、恶心呕吐、骨髓抑制等，CTCAE 分级
├─ 并发症管理    消化道出血、胆道梗阻、肠梗阻、感染
├─ 带管管理      PTCD、手术置管
└─ 血管通路管理   Port、PICC
```

「全程」的含义：从确诊到各线治疗，这些管理项**贯穿整个治疗过程**，不是一次性事件。命名比「照护管理」更准确地表达了「持续跟踪」的意思。

## 2. 营养管理

### 2.1 为什么胰腺癌营养要单独做

胰腺癌患者营养不良发生率在各类肿瘤中位居前列，机制特殊：

| 机制 | 表现 | 与普通肿瘤营养的区别 |
|---|---|---|
| **胰腺外分泌功能不全（PEI）** | 脂肪泻、体重下降 | 需**胰酶替代**，不是单纯「多吃」 |
| 胆道梗阻 | 脂肪吸收障碍 | 需先解决梗阻 |
| 胃排空障碍 | 早饱、恶心 | 需分餐、药物 |
| 肿瘤消耗 | 静息能量消耗升高 | 能量需求高于常规估算 |
| 治疗毒性 | 食欲下降、口腔黏膜炎 | 与毒性管理联动 |

因此**不能只做一个 BMI 计算器**。

### 2.2 评估工具

| 工具 | 用途 | 说明 |
|---|---|---|
| **BMI + 体重变化** | 基础筛查 | 体重下降 ≥5%/1 月或 ≥10%/6 月为警戒 |
| **PG-SGA** | 肿瘤专用营养评估 | 患者自评版（PG-SGA SF）可自行填写，是肿瘤营养的**金标准筛查工具** |
| **NRS-2002** | 住院患者筛查 | 常用于入院评估 |
| **能量摄入估算** | 实际 vs 目标 | 24 小时膳食回顾或简化的摄入记录 |
| **胰酶替代记录** | PEI 管理 | 是否使用、剂量、效果（脂肪泻是否改善）|

**首期推荐**：BMI + 体重变化（自动，从指标记录派生）+ PG-SGA SF（患者自评）+ 能量目标与实际摄入的差距。

### 2.3 能量计算公式（依据）

**依据**：《中国肿瘤营养治疗指南2020》胰腺癌章节

> 胰腺癌患者推荐能量 **25～30 kcal/(kg·d)**，蛋白质 **1.2～2.0 g/(kg·d)**，视患者营养及代谢状况变化调整。**有并发症者，能量可增加至 30～35 kcal/(kg·d)**。（A 级推荐）

| 项 | 默认 | 说明 |
|---|---|---|
| 能量系数 | **30 kcal/kg/天** | 取推荐区间上限（偏低体重者更适用），可手动调整 |
| 区间提示 | 25–30 | 无并发症时的指南推荐区间 |
| 并发症时 | 30–35 | 合并并发症可上调，界面同时展示 |
| 蛋白质 | 1.2–2.0 g/kg/天 | 按体重换算成克数一并显示 |

**不需要单独输入身高**：能量按体重计算；身高只用于 BMI。因此界面的输入起点是**体重**（已有可直接取指标记录），BMI 由身高体重派生。

**必须呈现的三件事**（不能只给一个数字）：

1. **公式透明**：显示 `51.4 × 30 = 1542`，让用户看懂数字从哪来。
2. **指南区间**：即使默认取 30，也要显示 25–30 与 30–35 两档区间。
3. **免责**：目标值是估算，实际以医生或营养师意见为准。

### 2.4 页面结构：当前 → 目标 → 实际 → 差距

单条线性流程，四步横排，中间用箭头连接：

```text
当前体重  →  目标能量  →  实际摄入  →  差距
51.4 kg      1542 kcal     1200 kcal    -342 kcal
用于计算      按 30 kcal/kg  最近一次记录   还差 342（完成 78%）
              51.4 × 30=1542  [修改]      （差距段淡红底）
```

这一结构直接回答了「我该吃多少、现在吃了多少、还差多少」，不需要用户自己算。

下方补充：进度条、指南区间对照表（三个 `<dt>/<dd>` 行）、调整系数入口。

### 2.5 指标卡片：大数字 + 方向箭头

**布局**：4 张卡横排，**淡灰底**（`#F4F6F5`），不用彩色底。

```text
┌─────────────────┐
│ 体重      警示   │
│ 51.4 kg          │  ← 大数字（34px / 650）
│ ↓ -3.4 kg 较1个月前│  ← 箭头 + 变动值 + 时间跨度
│ 体重下降          │  ← 原因
└─────────────────┘
```

### 2.5.1 箭头颜色的判定规则（重要）

**颜色由「指标方向」决定，不由「箭头方向」决定。**

原因：同一个 ↑ 箭头，在不同指标上含义相反。白蛋白上升是改善；CA19-9 上升是恶化。如果颜色跟着箭头方向走，会出现「CA19-9 上升显示绿色」这种危险错误。

因此每个指标配置一个方向属性：

| 属性 | 含义 | 上升 | 下降 | 应用指标 |
|---|---|---|---|---|
| `up_good` | 上升为改善 | 绿 | 红 | 白蛋白、体重（在低体重区间） |
| `down_good` | 下降为改善 | 红 | 绿 | CA19-9、总胆红素、CRP |
| `range` | 需维持区间 | 黄（观察） | 黄（观察） | BMI（过高过低都不好） |

颜色语义：

| 颜色 | 含义 |
|---|---|
| 绿 | 朝有利方向变化 |
| 黄 | 需观察（含 `range` 类偏离，以及持平） |
| 红 | 朝不利方向变化 |

**界面必须写明这条规则**，否则用户会按直觉误读。界面文案：「同一个 ↑ 箭头，白蛋白上升为绿、CA19-9 上升为红，因此颜色由指标本身的性质决定，不由箭头方向决定。」

### 2.6 与看板、一图秀的关系

| 数据 | 来源 | 复用 |
|---|---|---|
| BMI、体重 | `Observation`（指标记录） | 看板营养维度 + 一图秀体重曲线**同一数据** |
| PG-SGA 得分 | `NutritionAssessment` | 看板营养维度 |
| 能量目标 | 用户或医生设定 | 营养管理内部 |
| 实际摄入 | `NutritionAssessment` | 营养管理内部 |

**BMI 自动从身高体重计算**，不让用户重复录入。这与用户之前提出的「数据模板要能创建和本地更新」一致。

### 2.7 措辞边界

| 禁止 | 使用 |
|---|---|
| 「你营养不良」 | 「BMI 17.8，低于 18.5」 |
| 「必须补充营养剂」 | 记录目标与实际的差距，不给补充剂推荐 |
| 「按这个食谱吃」 | 不提供具体食谱 |
| 具体能量处方 | 只呈现「记录的目标值」与「实际」，目标由医生设定 |

营养干预涉及胰酶剂量、肠内/肠外营养等医疗决策，**工作台只做记录与差距提示**。

## 3. 全程管理的四个子页

### 3.1 毒性管理

| 项 | 说明 |
|---|---|
| 看什么 | 活动性毒性的类型与 CTCAE 分级（CIPN、皮疹、恶心呕吐、骨髓抑制等） |
| 口径 | `ToxicityRecord` 中未标转归的记录 |
| 分级 | 良好：无或均 1 级 / 关注：2 级 / 警示：≥3 级 / 未评估：未记录 |
| 界面 | 按治疗线分组，显示发生日期、分级、处理、转归 |
| 联动 | ≥3 级显示「建议尽快联系医生」（不给自行处理建议）；与营养管理联动（口腔黏膜炎→进食困难） |

### 3.2 并发症管理

| 项 | 说明 |
|---|---|
| 看什么 | 消化道出血、胆道梗阻、肠梗阻、感染 |
| 口径 | `ComorbidityStatus` 状态 + 相关客观指标 |
| 分级 | 良好：无 / 关注：既往或轻度异常 / 警示：活动且指标明显异常 |
| 界面 | 每项一行：状态 + 依据指标 + 记录日期 + 来源 |
| 联动 | 与带管管理联动（PTCD 与胆道梗阻）；与营养管理联动（胆道梗阻→脂肪吸收） |

### 3.3 带管管理

| 项 | 说明 |
|---|---|
| 看什么 | PTCD、手术置管的置入日期、位置、类型、维护记录、并发症 |
| 界面 | 每根管一张卡：类型、置入日期、已置入天数、上次维护、异常记录 |
| 提醒 | **不做自动提醒推送**，只显示「距上次维护 X 天」的中性事实 |
| 联动 | 与并发症管理双向（管路相关感染/堵塞） |

### 3.4 血管通路管理

| 项 | 说明 |
|---|---|
| 看什么 | Port、PICC 的置入、维护记录、并发症 |
| 界面 | 同带管管理 |
| 区别 | Port 与 PICC 维护周期不同，卡片上区分显示 |
| 联动 | 与毒性管理（静脉炎、血栓） |

### 3.5 列表页：2 列大卡片

**布局**：一行 2 张，2×2 网格，等宽等高。

```text
┌─ 毒性管理 ────────── 已有数据 ─┐ ┌─ 并发症管理 ──────── 已有数据 ─┐
│ 治疗相关不良反应的分级记录与监控  │ │ 主要并发症的状态跟踪与指标关联  │
│ ┌──────────────────────────┐ │ │ ┌──────────────────────────┐ │
│ │ 活动性毒性                │ │ │ │ 需关注                    │ │
│ │ 1 项  2 级 CIPN           │ │ │ │ 1 项  胆道梗阻活动         │ │
│ └──────────────────────────┘ │ │ └──────────────────────────┘ │
│ CIPN · 皮疹 · 恶心呕吐 · 骨髓抑制│ │ 消化道出血 · 胆道梗阻 · 肠梗阻 · 感染│
│ 记录于 2026-10-06   关联二线治疗│ │ 记录于 2026-10-08  总胆红素 3.2│
└──────────────────────────────┘ └──────────────────────────────┘
┌─ 带管管理 ────────── 尚无数据 ─┐ ┌─ 血管通路管理 ────── 尚无数据 ─┐
│ …                            │ │ …                            │
└──────────────────────────────┘ └──────────────────────────────┘
```

### 3.5.1 主题图标

四个主题各有一个**扁平化线性图标**（24×24，内联 SVG，非 emoji 非字体图标）：

| 主题 | 图标造型 | 含义 |
|---|---|---|
| 毒性管理 | 盾牌 + 惊叹点 | 防护与警戒 |
| 并发症管理 | 心电波形 + 警示点 | 器官功能监测 |
| 带管管理 | 管道 + 引流口 | PTCD / 置管 |
| 血管通路管理 | 血管通道 + 端口 | Port / PICC |

**颜色规则（关键）**：

| 状态 | 图标颜色 |
|---|---|
| **默认（无特殊数据）** | **扁平灰 `#9AA9A2`** |
| `watch` 关注 | 金色 `#B8860B` |
| `alert` 警示 | 红色 `#C0392B` |
| `unknown` 无数据 | 扁平灰 `#9AA9A2` |

即：**图标平时是低调的灰色装饰，只在有特殊情况时转为对应的状态色**。这样用户扫一眼就能从图标颜色看出哪一项需要处理，而不需要读文字。

**一致性要求**：图标出现在三处，颜色规则必须一致：

1. 全程管理列表的大卡片
2. 全程管理详情页的页面标题
3. 看板的全程管理缩略块

**实现注意**：颜色通过父容器的 `lv-*` 类 + `currentColor` 传递，不在每个图标上写死。详情页也必须带 `lv-*` 类，否则会退化为灰色（这是一个已修复的缺陷）。

**替代关系**：图标**取代了原来的状态点**（`.sdot`）。理由是状态点与文字标签重复表达同一信息，而图标同时承担「识别主题」与「指示状态」两个职责，信息密度更高。

**五层信息结构**（自上而下，层次固定）：

| 层 | 内容 | 样式 |
|---|---|---|
| 1 | 标题 + 状态徽标 | 状态点 + 16px/640 标题，右侧徽标 |
| 2 | 一句话说明 | 13px 灰，**固定最小高 42px**（保证两行对齐） |
| 3 | **关键指标**（淡灰底块） | 标签 + **26px 大数字** + 副说明 |
| 4 | 覆盖范围 | 12.5px，列出该管理项包含的子项 |
| 5 | 页脚 | 左侧最近记录日期，右侧关联线索 |

**对齐规则**（实测断言）：

| 断言 | 说明 |
|---|---|
| 第 1、2 张卡片 top 相同 | 一行两张 |
| 第 3、4 张卡片 top 相同且大于第一行 | 正确换行 |
| 左列 x 相同、右列 x 相同 | 两列对齐 |
| 四张卡宽度完全相同 | 等宽 |
| 同行两张高度相同 | 等高 |

等高靠 `margin-top: auto` 把页脚推到底部，而不是靠固定高度。

**状态色**：只用在**左侧 3px 竖线**与**徽标底色**上，卡片主体保持白底。这样既传达了级别，又不制造色块干扰（延续 §4.2.1 降噪原则）。

**窄容器**（W < 760px）：改为单列，四张卡各自一行。

### 3.6 四个子页的共性规则

1. **一期全部只做「查看与记录」，不做自动提醒**：推送提醒在医疗场景容易造成焦虑与责任争议。
2. **分级沿用红绿灯五级**（见 [DASHBOARD-SPEC §1.2](./DASHBOARD-SPEC.md)），但红色仍只表示客观异常。
3. **每项都要能回到来源资料**（证据链原则）。
4. **与看板对应维度同源**，不做第二份数据。

## 4. 三处数据联动

营养、心理、全程管理不是孤岛：

```text
营养管理 ──┬── 看板营养维度
           ├── 一图秀体重曲线
           ├── 并发症管理（胆道梗阻→脂肪吸收）
           └── 毒性管理（口腔黏膜炎→进食困难）

心理支持 ──┬── 看板心理维度（不用红绿灯，见 PSYCH-CARE-SPEC §8）
           └── 全程管理（长期毒性→情绪影响）

全程管理 ──┬── 看板并发症/毒性维度
           ├── 临床匹配（并发症状态是入排条件输入）
           └── 营养管理（如上）
```

**关键复用**：并发症状态同时是**临床匹配的输入**（[MATCHING-SPEC §2.1](./MATCHING-SPEC.md)）与**全程管理的展示对象**。必须是同一份 `ComorbidityStatus` 数据。
