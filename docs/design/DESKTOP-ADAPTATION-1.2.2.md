# 小胰宝 · DSH Desktop 工作台适配设计（1.2.2）

状态：设计基线，部分已有代码，尚未完成 Desktop 实机验收。  
对照：DSH 选址工作台 1.2.2 README、随当前本机 Desktop 提供的 `workbench-standard.zh.md`、小胰宝当前客户端实现。

## 1. 目标布局

小胰宝以患者照护业务为主任务，固定采用宿主分栏：

- 左侧业务工作台默认占主内容区域 **65%**，展示一个患者档案当前选中的业务 Tab。
- 右侧是 **唯一的 DSH Desktop 原生 Agent 会话区**，由宿主提供并渲染；工作台不实现第二套聊天界面。
- 左侧业务区域可通过 Desktop 支持的折叠控制收起/展开。不能覆盖或模拟宿主分隔条，不能把面板画到 Desktop 分配的区域之外。
- Desktop 侧栏、工作台入口、设置、模式切换器、公共导航和会话工具栏都由宿主负责。插件不得重建、遮挡或替换。
- 七个业务 Tab 共用当前患者和业务数据状态。切 Tab 不新建会话、不清空或覆盖右侧原生草稿。

注册配置：仓库身份使用 `https://github.com/xyb-openharness-dsh-plugins/xyb-workbench`，唯一工作台由 `desktopWorkbenches.register()` 注册；声明 `businessSide: 'left'`、`businessWidth: 0.65`，不启用 `customFrame`，由 Desktop 标准分栏承载原生会话和业务面板。目标机 DSH Desktop 版本应通过本地实测确认；不要把选址工作台 README 中 `customFrame: true` 的布局直接套用到此工作台。

## 2. 宿主责任与业务责任

| 能力 | DSH Desktop 宿主负责 | 小胰宝工作台负责 |
| --- | --- | --- |
| 左侧侧栏、模式切换、公共导航、设置 | 绘制与交互 | 不覆盖、不复制 |
| 原生 Agent 会话 | 创建/打开、当前会话切换、模式/模型/工具/权限、发送与运行 | 只调用公开接口；不自绘聊天、不过度授权、不自动发送 |
| 工作台注册与归属 | 仓库身份校验、入口、会话 owner 绑定 | `register()` 声明仓库；调用 `ensureSession()`；必要时核验 `ownsSession()` / `isActive()` |
| 患者档案和医疗事实 | 不持有小胰宝业务规则 | SQLite、附件、事件、指标、订阅、导出及跨 Tab 单一事实源 |
| Agent 上下文 | 维护原生会话草稿和实际执行 | 生成最小化、可审阅的页面/患者摘要并追加到原生草稿；由用户决定发送 |

模式、模型、工具和权限均遵循会话创建者在 DSH 原生会话中的设置。工作台不得隐式切换模型、创建第二个 Agent runtime、自动提交草稿、改变会话 owner，或将患者内容广播给其他会话。

## 3. 业务项目与原生会话映射

小胰宝的“业务项目”定义为患者档案；它不等同于 DSH 工作区或会话。一个患者可被多个有明确归属的工作台会话使用；一条 DSH 会话最多绑定一个工作台 owner。切换患者不会改写既有会话归属。

新增患者的流程：

1. 用户在小胰宝内填写患者档案。创建本机患者数据前，确认本机资料根已由用户显式选择。
2. 工作台请求 Desktop 为该业务项目建立并打开小胰宝 owner 的原生会话；请求重复时复用同一进行中的 promise，避免双击创建多个会话。
3. 会话打开后，把一条简短、无病情推断的可编辑开场白放入原生草稿，说明当前业务项目已建立及可用动作。用户自行检查和发送。
4. 如果 Desktop 创建/打开失败，保留已创建的患者档案，显示“会话未建立，可重试”；不得伪造会话 ID 或阻断之后离线整理患者资料。取消目录选择时不新建会话，不留孤立工作区。
5. 重新打开已有患者时，优先恢复该患者最近使用且仍由小胰宝拥有的会话；不存在时保留右侧 Desktop 原生空态和“创建/关联工作台会话”明确动作。不能自动接管普通会话或其他工作台会话。

会话与患者映射使用独立持久化记录，不把患者 ID 塞进 DSH session ID，也不把会话归属写进业务事实表。建议新增 `patient_session_binding`：`id`、`patient_id`、`dsh_session_id`（唯一）、`dsh_workspace_id`、`created_at`、`last_opened_at`、`status`。允许一位患者关联多条历史会话；每条会话只属于一个患者。Desktop 的 owner state 是会话归属的权威来源；本表只记小胰宝业务关联，启动时需检测两侧不一致并提供解绑/重试状态，不能擅自改写宿主 owner。

## 4. 工作区路径边界

不能把包含 SQLite 数据库和多位患者文件的整个小胰宝资料根，直接传给 `ensureSession({ folder })`。这会让 Agent 工作区超出当前患者业务范围。DSH 工作区与小胰宝资料根必须分别建模。

新建患者并需要工作区时，使用 Desktop 提供的用户目录选择/工作区创建流程，在用户确认后为该患者建立专用工作区；或在目标宿主正式支持的、经核实的隔离方式下创建患者专属目录。原始报告默认留在小胰宝资料根，仅将用户明确选择的材料/摘要复制或导出到该患者工作区。用户取消选择时不创建患者关联会话。患者删除、工作台卸载不得删除 DSH 会话和工作区。

后端 `ensureSession` 必须接收患者专用工作区路径，而不是当前 `dataRoot`。当前版本通过 `/api/xyb-workbench/agent-workspaces` 在工作台服务目录下创建按患者 ID 区分的空目录；只将该目录交给 `ensureSession`，页面摘要仍作为可编辑提示词写入原生输入框。目录不复制病历或 SQLite，也不自动发送。患者到会话的恢复暂以该患者最近一条 `agent_task.session_ref` 为索引，尚未实现独立的 `patient_session_binding` 表及同步状态管理。

## 5. 页面动作如何调用 Agent

每个 Tab 的“给我建议”按统一步骤工作：

1. 页面从当前患者同一事实源汇总已确认的数据，明确排除未确认的抽取候选。
2. 组装页面角色 prompt 和结构化 `inputSnapshot`，标注日期、单位、来源和缺失值；避免把整个数据库或不相关患者信息带入。
3. 验证工作台仍在前台、会话由小胰宝拥有且为当前可用会话。没有会话时，在该按钮处引导创建/选择会话，不阻塞其它页面功能。
4. 调用原生输入框的公开草稿接口，只追加到正确会话草稿；保留已有草稿、引用卡和正在发送状态，不自动发送。
5. 把 `agent_task` 与 `patient_session_binding` 关联，记录角色、prompt 快照、业务输入快照 hash 和 session ref。Agent 输出只有经用户确认后才形成可写入事实；不得把草稿、Agent 建议或未审核抽取当作医疗事实。

会话状态切换时不向非前台会话写入内容。重复点击、异步切换患者或工作台期间需用请求序号/取消信号防止旧任务覆盖当前选择。错误提示具体说明是未选择患者、没有 owner 会话、草稿接口不可用还是 Desktop 尚未就绪。

## 7. 实施顺序与验收

1. 目标 Desktop 版本能力核对：记录版本/系统架构；确认 `customFrame`、layout、native conversation 可见性、业务区折叠以及 `ensureSession` 的当前合同。实现后不以“注册成功”代替分栏验收。
2. 客户端适配层：集中封装创建/恢复原生会话、owner 验证、保存患者关联和草稿追加；禁止页面各自直接猜测宿主 API。
3. 数据层迁移：增加患者—会话业务映射及恢复状态；为孤儿/卸载/owner 不一致状态定义可修复处理，不改变 DSH 真正归属。
4. 业务流程：新建患者时建立/打开会话；已有患者恢复映射；AI 动作追加到当前正确的原生会话草稿；离线业务面板在无会话时仍完整可用。
5. 完整包 `npm run check` 与 `npm pack --dry-run`；本机安装后按 Desktop 指引重启。
6. 实机验收：业务区 65% 左侧、可折叠；右侧仅有原生会话；7 个 Tab 切换时会话保持同一实例；模式切换、模型/工具/权限仍由原生控制；新增患者创建并打开小胰宝会话；取消/失败/重复点击/快速切换患者；草稿保留且没有自动发送；侧栏、设置和公共导航完整可见。

未完成任一实机项时，在状态报告中明确标为未验证。若当前 Desktop 的 `customFrame` 行为与参考 README 不一致，按目标版官方 API 和用户指定体验调整注册模式，不修改宿主全局导航或复制聊天 UI。
