## v3 HTML 界面移植进度（0.1.8）

本轮以 `prototype-v3.html` 的浅色视觉、左侧模块导航、顶部状态、患者条和页面节奏为参照，将 React 面板从临时表单布局改为工作台布局。看板按「现在可以做 → 周期计划与未来两周 → 当前变化提醒 → 七个近况维度 → 持续记录」排列。看板数值来自现有本机读模型；缺少结构化事实时显示“尚无记录”，没有使用原型中的模拟患者数据。

一图秀按肿瘤标志物、血常规、肝功能、感染与炎症、肾功能、代谢与营养、其他指标分类。`GET /api/xyb-workbench/observations/history` 从已确认的 `observation` 读取每项最近五次数据；指标卡片默认显示最新结果及与前次差值，点击后显示固定 SVG 坐标的趋势线；单位不同的记录不连线。营养管理的体重、BMI 和摄入能量卡片使用相同交互。首页变化提醒按指标类别汇总，左侧列变化，右侧列供医生核对的事项；影像变化在原文跨页核对实现前明确标为待核对。页面顶部增加大字切换和本机资料位置入口。患者切换、资料导入核对、指标录入、试验检索与收藏、营养记录、治疗周期和建议任务沿用现有本机接口。

病情整理页现有「查看原件 → 解析 → 核对候选」的单文档闭环。`GET /api/xyb-workbench/documents/content?documentId=…` 只按数据库内相对资料路径读取，拒绝越出资料根的路径；PDF、图片与文本可在弹窗预览，DOCX 仍只归档并提示解析能力限制。

`npm run check` 通过：5 个 Node 测试、Schema contract 校验和客户端、服务端语法检查；测试覆盖文档预览字节、预览 API 和资料路径越界拒绝。已用 `npm pack` 生成 `xyb-openharness-dsh-plugins-xyb-workbench-0.1.8.tgz`，包内包含客户端、服务端、`cordis.patch.yml`、迁移和离线试验库。Desktop 活动 profile 的 `package.json` 已指向 0.1.8 包。安装使用 Desktop 随包的 pnpm 10；外部 `dsh` CLI 内置 pnpm 9，与活动 profile 的 pnpm 10 store 不兼容。

实机曾显示新侧栏、七个入口和“AI成炬，照亮前路”标题，证明新客户端布局可加载。该观察发生在 0.1.4 热更新阶段；旧服务端尚未提供新增历史路由，导致当时选患者未能进入详情。0.1.5 起客户端对历史路由暂时不可用做降级处理。**0.1.8 的服务端路由、原件预览和完整患者详情仍待 Desktop 完整退出重开后实测。**自动审批拒绝了由 Agent 退出 Desktop，理由是可能丢失未保存会话，且要求用户自行完整退出并重新打开；因此没有绕过该限制，也未把安装成功写成实机验收通过。

仍未与 v3 完全对齐的部分：报告页级抽取与跨页比对、分子/IHC结构化档案、临床规则评估和来源版本、营养需求计算与 PEI、心理量表和经核验资源、毒性/并发症/管路详情，以及 PDF/JPEG 导出。具体当前状态以新增对照表为准。
