# 病情报告生成设计

## 决策

使用 **专用报告生成 Skill + DSH Agent 编排**。

Agent 适合接收用户意图、选择报告范围、解释缺失字段、启动任务和打开结果。报告生成需要稳定的结构、可复现的版式和多格式文件输出，应由独立 Skill 执行，不能完全依赖 Agent 的自由文本输出。

## 输入契约

工作台只提交已确认的本机记录，以及每个字段的来源、日期和确认状态。未确认或不存在的字段输出为“未记录”或“待核对”，不由 Agent 推断。

```json
{
  "report_type": "full | visit_summary | trial_consultation",
  "patient": { "display_name": "", "birth_year": null, "sex": null },
  "confirmed_facts": [],
  "trends": [],
  "treatments": [],
  "source_index": [],
  "missing_items": [],
  "output_formats": ["pdf", "html", "jpeg"]
}
```

## 统一报告结构

1. 封面与生成说明：生成时间、报告范围、本机资料说明。
2. 基本信息与资料完整度。
3. 诊断、病理与分子信息：逐项附来源。
4. 治疗与关键事件时间线。
5. 指标趋势：保留单位、参考范围、数据来源和图表说明。
6. 营养、症状和照护记录。
7. 临床试验咨询线索：只展示已收藏或用户选择的线索，明确最终由研究中心确认。
8. 待补资料与来源目录。

## 输出流程

1. 工作台生成冻结的结构化快照。
2. Agent 将快照和报告类型交给报告生成 Skill。
3. Skill 用固定模板生成 HTML。
4. Skill 从同一份 HTML 生成 PDF 与逐页 JPEG，并保存到用户选择的本机目录。
5. Agent 返回文件路径、生成日志和无法包含的字段；用户可在工作台打开或重新生成。

## 约束

- 不调用模型补写患者事实、诊断、疗效、预后或治疗建议。
- 所有临床字段都显示来源或“未记录”。
- HTML、PDF、JPEG 使用同一个冻结快照，避免格式间内容不一致。
- 报告模板、图片、样式和生成器随工作台包安装；患者数据与导出文件留在本机。
