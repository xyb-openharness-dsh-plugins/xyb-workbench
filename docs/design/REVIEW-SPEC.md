# 小胰宝工作台 · 报告核对规格（多文档 · 多页面）

日期：2026-10-13 · 状态：**设计建议稿。单文件多页异构问题来自对真实病历的实测。**

上级文档：[EXTRACTION-SPEC.md](./EXTRACTION-SPEC.md)（抽取链路） · [CASE-TEMPLATE-SPEC.md](./CASE-TEMPLATE-SPEC.md)（字段规格）。

本文解决两个问题：**多个文档怎么核对**、**一个 PDF 里多页异构内容怎么处理**。

---

## 1. 问题：实测发现的三层复杂性

对真实病历（李菊病历.pdf）逐页实测：

| 页 | 字符数 | 内容 |
|---|---|---|
| p1 | 746 | 病情介绍（基本信息 + 基因 + 病理） |
| p2 | 523 | 既往治疗史（文本） |
| **p3** | **8** | 各阶段肿标变化 —— **表格图片** |
| **p4** | **8** | 各阶段血像 —— **表格图片** |
| p5 | 454 | 近期 CT 检查 |
| p6 | 797 | 诊断意见 |

**三层复杂性**：

| 层 | 问题 |
|---|---|
| **① 多文档** | 一次导入 10+ 份文件，逐份核对没有进度感 |
| **② 多页面** | 一个 PDF 有 6 页，每页内容不同，需要页级导航与定位 |
| **③ 页内异构** | 同一 PDF 里，p1/p2/p5/p6 是文本，**p3/p4 是表格图片** |

**关键发现**：p3/p4 只有 8 个字符的文本（一个标题），**实际表格在图片里**。这类页面必须走 OCR（MinerU），纯文本提取拿不到数据。

这直接决定了：**解析方式必须按页判定，不能按文件判定。**

## 2. 数据模型

在现有 `Document` 之下新增 `Page` 层：

| 实体 | 关键字段 |
|---|---|
| `Document` | 现有字段 + `pageCount`、`parseStatus` |
| **`Page`** | `pageId`、`documentId`、`pageNo`、`textLength`、**`contentType`**、`hasTable`、`hasImage`、`parseMethod`、`parseStatus` |
| `CandidateFact` | 现有字段 + **`pageId`**（从"哪一页"来的）+ `bbox`（可选，定位框） |

**`contentType` 枚举**（页级）：

| 类型 | 判定依据 | 处理 |
|---|---|---|
| `text` | 文本量充足 | 本地提取 + 规则抽取 |
| `table-image` | 文本量极低 + 页面有图 | **必须 OCR**（MinerU） |
| `table-text` | 检出表格结构（HTML table / 对齐文本） | 表格重建 |
| `image-only` | 几乎无文本、无表格 | OCR 或标注"需人工查看" |
| `blank` | 空页 | 跳过 |

实测映射：p1→`text`，p3→`table-image`，p5→`text`。

---

## 3. 解析分流：按页而非按文件

```text
文件 → 拆页 → 逐页判定 contentType
  ├─ text        → 本地提取
  ├─ table-text  → 本地提取 + 表格重建
  ├─ table-image → 该页送 MinerU（其余页不受影响）
  ├─ image-only  → 送 MinerU 或标注人工
  └─ blank       → 跳过
```

**为什么按页**：一个 PDF 里只有 2 页需要 OCR，却把整份 6 页上传云端，既慢又扩大了隐私暴露面。

**按页处理带来三个好处**：

1. **减少上传**：只传真正需要的页（实测 6 页里只有 2 页需要）
2. **并行与增量**：文本页立刻可用，图片页排队 OCR，不互相阻塞
3. **隐私最小化**：上传范围可精确告知「将上传第 3、4 页」

**页级解析方式必须记录下来**并在界面显示（「本页由 MinerU 解析」/「本地提取」），便于用户判断可信度。

## 4. 界面：三栏 + 双导航

### 4.1 布局

```text
┌─ 报告核对 ──────────────────────────────────────────────────────┐
│ [按文档] [按指标] [仅看待处理]          已确认 7/12 · 待核对 5    │
├────────────┬────────────────────────────────┬───────────────────┤
│ 文档 (12)   │ 李菊病历.pdf                   │ 候选字段（3 待确认）│
│            │ 第 2 / 6 页 · 本地提取          │                   │
│ ✓ 化验单10-08│ ┌──────────────────────────┐  │ 采样日期 2026-10-08│
│   12项 已确认│ │                          │  │ 指标名  总胆红素    │
│ ▶ 李菊病历  │ │      （原件 / 解析文本）    │  │ 数值    3.2       │
│   6页 · 3待核│ │                          │  │ 单位    mg/dL     │
│   ①②③④⑤⑥ │ │                          │  │ 参考范围 0.3–1.2   │
│ ○ CT报告    │ └──────────────────────────┘  │ 来源    第 1 页    │
│   3页 · 未开始│ [上一页] 1 2 3 4 5 6 [下一页] │ 原始片段 "总胆红素 3.2"│
│ ○ 病理07-20 │                                │ [确认][跳过][排除] │
│ ○ 基因08-02 │                                │                   │
├────────────┴────────────────────────────────┴───────────────────┤
│ [确认并下一项]                              ← 主操作固定底部      │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 左栏：文档来源 list

**这是当前缺失的部分。** 每份文档显示：

| 元素 | 说明 |
|---|---|
| 状态图标 | `✓` 已完成 / `▶` 进行中 / `○` 未开始 / `!` 有冲突或失败 |
| 文件名 | 超长截断，悬停显示全名 |
| **页数** | 「6页」，让用户知道规模 |
| **进度** | 「3 项待核对」「12项 已确认」 |
| **页级状态点** | `①②③④⑤⑥` 每页一个小点，表示该页有无疑点 |

**页级状态点的价值**：用户一眼看出「这份 6 页的病历，问题在第 3 页」——第 3 页是需要 OCR 的表格图片，最容易出错。点击小点直接跳到该页。

**排序**：默认按「待核对数量」降序（有事的排前面），可切换按文件名 / 日期。

### 4.3 中栏：页面导航

| 元素 | 说明 |
|---|---|
| 页标题 | 「第 2 / 6 页」+ **解析方式**（本地提取 / MinerU 解析） |
| 页面内容 | 原件渲染 或 解析文本，可切换 |
| 底部分页器 | `[上一页] 1 2 3 4 5 6 [下一页]`，当前页高亮 |
| 页级标记 | 该页有疑点时页码上加标记 |

**必须显示解析方式**：用户有权知道这一页的文本是本地提取的还是云端 OCR 的——后者出错概率更高，值得多看两眼。

### 4.4 跨页/跨文档比对

同一指标可能出现在多页：

```text
┌─ 页内比对提示 ──────────────────────────────┐
│ 本页「CA19-9」与以下记录不一致：              │
│ · 第 3 页（表格图片）CA19-9 = 120           │
│ · 化验单10-05        CA19-9 = 122           │
│ [并排查看]  [查看差异]                       │
└────────────────────────────────────────────┘
```

「并排查看」打开一个双栏对比视图，左右各显示一页的相关片段。

## 5. 页内异构：三种页型的核对差异

不同 `contentType` 的页面，核对界面不同：

### 5.1 文本页（`text`）

常规：左侧原文、右侧候选字段。

### 5.2 表格页（`table-text` / `table-image`）

**表格重建后逐行映射**：

```text
┌─ 原始表格（重建后）─────────────┬─ 候选记录 ─────────────┐
│ 日期        │ 项目   │ 结果    │                          │
│ 2024-10-10 ▶│ CA19-9 │ 543    │ ← 当前行，右侧对应字段    │
│ 2024-12-01 │ CA19-9 │ >800   │                          │
│ 2025-02-04 │ CA19-9 │ 45     │                          │
└────────────────────────────────┴──────────────────────────┘
```

**点表格行 → 右侧显示该行的候选记录**。一次核对一行，不混淆。

**表格图片页额外提示**：

```text
本页为表格图片，已由 MinerU 识别。识别结果可能有偏差，请对照原图核对。
[查看原图]  [切换为并排对照]
```

### 5.3 一次多行确认

上例中三行 CA19-9 可批量确认：

```text
本页识别出 3 条 CA19-9 记录
[全选] [全不选]
☑ 2024-10-10  543
☑ 2024-12-01  >800
☑ 2025-02-04  45
[确认选中 3 条]
```

**注意**：这是「**本页内**批量」，不是跨文件「一键全确认」。仍然要求用户看过这一页。见 [EXTRACTION-SPEC §4.7](./EXTRACTION-SPEC.md) 对批量操作的约束。

**比较符必须保留**：`>800` 不能变成 `800`。

## 6. 与解析链路的关系

```text
导入文件
  → 拆页，逐页判 contentType
  → text 页：本地提取（立即可用）
  → table-image 页：排队 MinerU（需用户已启用云端 + 同意上传）
      └─ 上传前告知：「将上传第 3、4 页共 2 页」
  → 表格重建
  → 生成候选记录（带 pageId）
  → 进入核对
```

**跨设备/跨时间续做**：页级状态独立持久化。文本页核完了，图片页 OCR 还没回来，用户可以先把文本页确认掉，OCR 完成后再回来处理。

## 7. 失败与降级

| 情况 | 表现 |
|---|---|
| 整份文件无文本层 | 标「扫描件」，提示需要 OCR |
| **单页无文本层**（如 p3） | 该页标 `table-image`，**其余页正常** |
| 该页 OCR 失败 | 该页标失败 + 原因；**不影响其他页** |
| 用户未启用云端 | 图片页标「需 OCR，但云端解析未启用」+ 跳设置 |
| 用户拒绝上传该次 | 该页标「未解析」；可手工录入 |
| 表格重建异常 | 显示原始 Markdown + 标「表格可能不完整」 |
| 页数与实际不符 | 显示「检测到 N 页，请核对」 |

**核心原则：单页失败不能拖垮整份文件。** 这是按页分流的直接收益。
