## 1. 为什么需要统一设置页

### 1.1 现状问题

配置散落在各模块：

| 配置项 | 当前位置 | 问题 |
|---|---|---|
| 检索渠道启用/状态 | 临床匹配 → 渠道配置 | 用户找「设置」时会先去顶栏 |
| MinerU token | 无 | 未设计 |
| 业务资料根目录 | 资料库 → 资料位置 | 埋在二级页 |
| 备份与恢复 | 无正式入口 | 未设计 |

用户已经形成了「设置应该有个统一地方」的预期。分散的配置让每个新能力都要重新决定放哪。

### 1.2 为什么不新增一级 Tab

一级 Tab 已经是 7 个（看板/病情整理/病情一图秀/临床匹配/营养管理/心理支持/全程管理）。

**设置不是一级任务，是低频配置。** 把它提为一级 Tab 有两个代价：

1. 挤占导航宽度（实测 1280px 已接近临界，见 UI-DESIGN）
2. 每天看病情的人和每月改配置的人共用同一排导航，权重错配

**结论：用顶栏齿轮入口，不占一级 Tab。**

## 2. 入口与位置

```text
┌─ 小胰宝        患者 ▾          资料留在本机   ⚙ 设置   ✧ AI 协助 ─┐
```

- 齿轮位于「AI 协助」左侧，顶栏右端
- 图标 + 文字（不只图标，避免猜测）
- 点击后打开设置弹窗，按 v3 分区完整呈现数据来源、文档解析、存储备份和工作台范围

**交互按用户最新要求**：采用 v3 模态弹窗；内容区独立滚动，关闭时回到原 Tab。此前“整页替换”的建议已被此决策覆盖。

**面包屑**：设置页左上角显示「← 返回 <原页面>」，返回时恢复原 Tab 与滚动位置。

## 3. 三组配置

```text
设置
├─ 01  数据来源        检索渠道的启用与状态
├─ 02  文档解析        本地提取 / MinerU 云端解析 + token
└─ 03  存储与备份      业务资料根、备份与恢复
```

### 3.1 数据来源

把原「临床匹配 → 渠道配置」迁移过来，内容不变（见 [MATCHING-SPEC §5](./MATCHING-SPEC.md)）：

- 本地数据：ChiCTR 归档 / CDE 归档 / CTV 索引
- 在线来源：ChiCTR 在线 / ICTRP
- 每项显示：状态、记录数、覆盖时间、最后检查时间、失败原因

**迁移后的处理**：临床匹配的「渠道配置」二级 Tab 保留，但改为**跳转到设置页**（不维护两份界面）。同时在设置页说明「此配置影响临床匹配的检索范围」。

### 3.2 文档解析

#### 3.2.1 解析方式选择

```text
○ MinerU 解析（默认推荐）
    默认使用随包的公益 API Token 调用 pipeline；用户 Token 可覆盖。
    凭据认证失败时提醒用户申请替换，并尝试 Flash 免费解析。
    · Flash 不需 Token，但所选文件会发送到 MinerU 云服务
    · 用户替换 Token 保存在本机 ~/.mineru/config.yaml，不回传到 UI 或写进患者库
    · TXT / MD / CSV 始终优先本地解析

○ 仅本地解析
    仅支持 TXT / MD / CSV 的本机抽取；PDF、图片和 Office 原件可归档，但不做 OCR。
```

**默认解析器为 MinerU；首次解析会先弹出云端说明并要求明确确认。**未确认前不上传、不调用 MinerU。Flash 与 API 都是云端处理；此处说明优先级取代本文件此前“仅本地作为默认”的旧决策。

#### 3.2.2 隐私告知（切到云端时必须展示）

首次使用 MinerU 时，设置弹窗内展示说明并要求用户勾选确认：

```text
启用后，你导入的扫描件与图片会上传到 MinerU 云端解析。
· 传输内容：仅你所选的文件本身
· 不会传输：患者档案、基因结果、治疗记录、收藏与笔记
· 处理方式：服务端解析完成后不保留
· 可随时关闭

[了解 MinerU 隐私政策]   [我了解，启用]
```

**必须点「我了解，启用」才生效**，不默认勾选。

#### 3.2.3 Token 替换与过期降级

```text
MinerU API Token（可选替换公益 Token） [ 输入新 Token ]
┌──────────────────────────────────────────────┐
│ sk-······································    │  ← 密码型，带显示/隐藏
└──────────────────────────────────────────────┘
[ 校验并保存 ]   [ 如何申请？ ]

状态：内置公益 Token · API 解析可用
```

**交互规则**：

| 规则 | 说明 |
|---|---|
| 密码型输入 | 默认隐藏，提供「显示」切换 |
| **只能校验，不能回显** | 保存后只显示后 4 位（`sk-····pJqM`），不提供「查看完整值」 |
| 保存前先校验 | 点「校验并保存」调用一次轻量接口；成功才写入 |
| 校验失败给原因 | 401 = token 无效；429 = 配额用尽；网络错误单独提示 |
| 用户 Token 覆盖 | `MINERU_TOKEN` 环境变量 > 本机 `~/.mineru/config.yaml` > 随包公益 Token |
| 过期回退 | 认证失败时提醒用户申请新 Token，并自动尝试 Flash；成功时明确显示为 Flash 降级解析 |
| Flash 限制 | 单个文件最多 10 MB / 20 页；超限或失败保留原件并提示申请新 Token 或稍后重试 |
| **不显示在日志/导出** | 见 §4 |

**「如何申请？」展开后**：

```text
1. 访问 mineru.net 并注册/登录
2. 进入「API」→「API 管理」页面
3. 创建 Token 并复制
4. 回到这里粘贴，点「校验并保存」

[ 打开 mineru.net/token 申请页 ]   ← 外部链接，点击前提示去向
```

**为什么应用内填入而不是引导用 CLI**：用户已经装好了工作台，再要求开终端跑 `mineru-open-api auth` 会挡住大部分人。工作台首次开箱用公益凭据；用户也可应用内替换自己的 Token。随包凭据会随公开安装包分发，使用前应确认公益配额策略和维护安排。

#### 3.2.4 解析模型

```text
解析模型
● pipeline（推荐）    面向病历优先保留来源内容，不做生成式补写
```

默认并固定为 pipeline，理由见 [RESOURCE-DEPENDENCIES §2.4](./RESOURCE-DEPENDENCIES.md)。VLM 可能生成原文中不存在的内容，因此当前病历流程不向用户提供 VLM 选项。

### 3.3 存储与备份

| 项 | 内容 |
|---|---|
| 业务资料根 | 显示当前路径 + 「更改位置」（走宿主目录选择器） |
| 已用空间 | 原件 / 派生文件 / 数据库分别占用 |
| 备份 | 「立即备份」+ 上次备份时间 + 备份位置 |
| 恢复 | 「从备份恢复」— 需二次确认，说明会覆盖什么 |

**不在这里放**：模型配置（宿主管理）、主题（宿主管理）、深色模式（跟随宿主）。**避免冒充宿主设置**。

## 3.5 Token 存放：复用 MinerU CLI 配置（**已确认**）

**决策：工作台与官方 CLI 共用 `~/.mineru/config.yaml`，不另建一套存储。**

### 3.5.1 已实测的文件格式

```yaml
token: sk-xxxxx
```

| 实测项 | 结果 |
|---|---|
| 文件路径 | `~/.mineru/config.yaml` |
| 格式 | 单行 YAML，唯一键 `token` |
| 文件权限 | `-rw-------`（0600，仅所有者可读写） |
| 目录权限 | `drwxr-xr-x`（`~/.mineru/`） |
| 文件大小 | 59 字节 |

格式极简，**只有一个键**，写入风险低。

### 3.5.2 已实测的 token 解析优先级

| 优先级 | 来源 | 实测 |
|---|---|---|
| 1 | `--token` 命令行参数 | 已验证参数存在 |
| 2 | `MINERU_TOKEN` 环境变量 | ✅ `Token source: env` |
| 3 | `~/.mineru/config.yaml` | ✅ `Token source: config` |

**实测细节**：用 `MINERU_TOKEN=sk-envtest... mineru-open-api auth --show` 会显示 `Token source: env`，确认环境变量覆盖配置文件。

无配置时 CLI 输出 `No token configured.` 并提示运行 `mineru-open-api auth`——**不会报错退出**，可安全探测。

### 3.5.3 复用带来的三个好处

| 好处 | 说明 |
|---|---|
| 单一来源 | 设置页填了，命令行立即可用；命令行配了，工作台立即可用 |
| 无重复 | 不会出现「工作台能用、CLI 报未配置」的困惑 |
| 兼容官方 | 用户若已按官方文档配过，工作台开箱即用，不用重填 |

### 3.5.4 复用的代价与对策

| 代价 | 对策 |
|---|---|
| 工作台要读写用户主目录下的文件 | 只读写 `~/.mineru/config.yaml` 一个文件，不碰该目录其他内容 |
| 与 CLI 版本耦合 | 写入时**保留其它已有键**（见下），不整体覆盖文件 |
| 文件可能被 CLI 改动 | 每次打开设置页重新读取，不缓存在内存里做权威 |
| 首次创建目录 | 若 `~/.mineru/` 不存在，需创建并设 0700 |

### 3.5.5 写入规则（实现要求）

```text
读取 ~/.mineru/config.yaml
  ├─ 不存在 → 创建，写入 token
  ├─ 存在且只有 token → 更新 token 值
  └─ 存在且有其它键 → 只更新 token，保留其它键
写入方式：先写临时文件 → 设置权限 0600 → 原子改名替换
```

**四条硬要求**：

1. **不整体覆盖**：保留文件中已有的其它键。未来 CLI 加字段时不会丢。
2. **权限 0600**：新建文件必须设为仅所有者可读写，与现有文件一致。
3. **原子写入**：临时文件 + rename，避免写一半被中断导致 token 损坏。
4. **不做其他解析**：只认 `token:` 行，不尝试解释 YAML 其他结构。

### 3.5.6 边界情况

| 情况 | 行为 |
|---|---|
| `~/.mineru/` 不存在 | 创建目录（0700）+ 创建文件（0600） |
| 文件存在但无 `token` 键 | 追加 `token:` 行，不删除原有内容 |
| 文件被外部占用/只读 | 报错并给出路径，提示用户检查权限；**不静默失败** |
| 用户同时用 CLI 改了 token | 设置页重新读取时看到新值；不提示冲突（本机单用户，无需处理） |
| 环境变量已设 `MINERU_TOKEN` | 设置页显示提示：「检测到环境变量 MINERU_TOKEN，其优先级高于此处配置」 |
| 磁盘只读 | 保存失败，明确报错，不假装成功 |

**最后一条尤其重要**：如果 `MINERU_TOKEN` 环境变量存在，界面上填的 token 会被它覆盖，用户会困惑「为什么填了没用」。检测到就提示，不猜。

## 4. 密钥安全（重要）

Token 是凭据，处理规则比普通配置严：

| 规则 | 说明 |
|---|---|
| **存储位置** | `~/.mineru/config.yaml`（与 CLI 共用，见 §3.5），**不写业务资料根**（业务根可能被备份/导出/共享） |
| **不回显** | 保存后只显示后 4 位；不提供查看完整值 |
| **不进日志** | 日志中一律脱敏为 `sk-****`；错误信息不含 token |
| **不进导出** | 备份、诊断包、汇总导出都不含 token |
| **不进 AI 上下文** | 不发送给任何模型 |
| **卸载不删** | 与应用数据同生命周期，卸载插件保留（用户重装无需重填） |
| 明示存储位置 | 设置页说明「Token 保存在本机应用数据目录，不会离开这台设备」 |

**「不会离开这台设备」这句要准确**：token 会随请求发给 MinerU（那是它的用途），但不会被发到其他地方。措辞应写「Token 仅用于向 MinerU 发起解析请求」。

**注意**：token 存在用户主目录（`~/.mineru/`），不在工作台的应用数据目录内。因此：

| 影响 | 说明 |
|---|---|
| 卸载工作台 | token 保留（属于 CLI 的配置，不由工作台管理） |
| 备份业务资料根 | 不含 token（业务根在别处，天然隔离） |
| 用户查看/清理 | 可直接看 `~/.mineru/config.yaml`，或跑 `mineru-open-api auth` |

设置页应说明存放路径，让用户知道它在哪里、如何自查。

## 5. 状态矩阵

| 场景 | 表现 |
|---|---|
| 未配置 token + 选云端 | 保存按钮禁用，提示「请先填写 Token」 |
| token 无效（401） | 行内错误：「Token 无效，请确认已复制完整」+ 重新申请链接 |
| 配额用尽（429） | 提示「配额已用尽」，仍可切回仅本地 |
| 校验时无网络 | 提示「无法连接 MinerU，请检查网络」；**不保存** |
| 已配置 | 显示 `sk-····pJqM` + 「校验通过」+ 移除按钮 |
| 关闭云端解析 | 保留 token（下次开启不用重填），状态改为「已配置，未启用」 |
| 用户拒绝隐私告知 | 不启用云端；解析方式保持「仅本地」 |
