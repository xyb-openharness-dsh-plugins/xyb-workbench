1 · 产品与边界

1.1 定位

小胰宝工作台是面向胰腺癌患者与家属的本地资料整理与信息匹配工具，以 DSH Desktop 插件面板形态运行。核心价值：把零散的化验单、病理报告、基因报告整理成可核对的档案，再据此匹配公开登记的临床试验。

1.2 核心用户流

  1. 建档：选择或新建患者档案（看板首屏引导两卡）。
  2. 导入核对：上传资料 → 解析 → 逐条确认字段 → 形成已确认记录。
  3. 看板总览：七维度红绿灯 + 需关注项 + 资料完整度。
  4. 匹配：从已确认档案生成入组档案 → 检索试验 → 规则逐条判定（四类分组）。
  5. 日常管理：一图秀看趋势、营养算能量、心理自评、四项全程管理。

1.3 硬性边界（不得违反）

边界要求
不做诊断全站不生成诊断、疗效判断、用药建议。所有归纳页脚必须写明「只归纳已确认事实，不包含诊断」。
不替代医生能量目标标注「应以医生或营养师意见为准」；情绪页标注「工作台不判断你的情绪状态」。
数据不出本机顶栏常驻「资料留在本机」状态点；情绪数据页脚「只保存在本机，不发送给任何模型」。
云端需明示选择 MinerU 云端解析前，必须列出传输内容 / 不传输内容 / 处理方式 / 可随时关闭四项，且需勾选确认。
演示可辨识演示数据必须显式标注。原型用 .demo-ribbon 条 + 纸张视图内 paper-demo 双重标注。
不覆盖宿主保留 DSH 公共导航、设置、模式切换、原生 Agent 会话。设置页脚须声明「宿主设置由 DSH 管理」。
AI 会话走宿主「✧ AI 协助」按钮只打开宿主会话示意面板，不自行实现聊天输入、模型调用或发送。
演示数据规则：原型中所有患者、报告、试验、规则与数字均为虚构。真实实现中种子数据与清理脚本只作用于明确标记的演示记录，不得读取或清理真实用户记录。

2 · 技术架构

2.1 单文件结构

原型为单文件自包含 HTML：一份 <style>（1–928 行）+ 一个 42KB 的 .frame 静态壳行 + 一段 IIFE 严格模式 <script>。零外部依赖、零网络请求、零构建。

<!DOCTYPE html> <head> meta / title / <style>（设计令牌 + 组件 + 响应式） <body> div.review-tools · 设计评审工具条（原型专用，正式版可删） div.demo-ribbon · 演示声明条 div.desktop#desktop aside.host#host · DSH 宿主只读示意（196px 侧栏） div.frame#frame · container: workbench / inline-size ├─ header · brand + patient-picker + local-state + settingsOpen + aiOpen ├─ nav.main-tabs · 7 个 role=tab 按钮 ├─ main#content.page · role=tabpanel（唯一动态渲染区） └─ aside#assistant · 宿主 AI 会话示意（默认 hidden） dialog#modal · toast#toast · #live(aria-live) <script> 'use strict'（数据 → 渲染函数 → 注册表 → render → 事件委托）

2.2 脚本模块顺序（严格按此顺序组织，否则 TDZ 报错）

  1. 工具函数：esc(HTML 转义)、$、$$。esc 必须用于所有用户可控字符串，防 XSS。
  2. 演示数据常量（见第 5 章）：LV / patients / documents / treatmentLines / molecular / ihcPanel / trials / rules / channels / careItems / ACCESS_DEVICES / CARE_ICONS / nutrition / scales / resources / CRISIS / METRIC_DIR / ENERGY_FORMULA / GENE_INFO / CATS / CATALOG / READINGS / seriesA / seriesB / medLines / remarks。
  3. 调色与工具：IND_PALETTE / MAX_CHARTS / colorFor / IND_COLOR / careIcon / daysSince / arrowFor / indStatus。
  4. state 单例状态对象。
  5. 页面 HTML 生成函数（每页一个纯函数，返回 HTML 字符串，不碰 DOM）。
  6. PAGES 注册表：key → { html: fn, tab: elementId | null }。
  7. render() 与局部更新函数 renderTimelineRegions()。
  8. 事件委托：document click / change / input / blur / keydown。
  9. 初始化：render() + 绑定顶栏控件。

2.3 渲染策略

策略适用范围原因
整页 innerHTML 重建一级 / 二级 Tab 切换、患者切换、多数按钮简单可靠，原型可接受
区域局部重绘一图秀勾选指标 / 开关关键点 / 切换用药线源码注释明确：「全页 innerHTML 重建会让连续勾选丢失元素引用与输入焦点」
只改属性不改结构chip 的 aria-pressed、tl-legend 的 aria-pressed 与 opacity保持焦点、避免闪烁
只切 disabledToken 输入框输入时输入中不重建表单

2.4 与 DSH 工作台的集成点

  • 容器：.frame 使用 container-type: inline-size + container-name: workbench，所有响应式按容器宽度而非视口宽度收紧，保证嵌入宿主面板时表现一致。
  • 宿主壳：.host（196px）为只读示意，展示宿主的工作台选择器与会话列表；#hostToggle 可切换其显示。
  • AI 协助：#aiOpen 打开 aside#assistant（position:absolute; right:0; width:min(440px,100%)），内容为宿主会话占位。
  • 宽度模拟：#canvasWidth 提供 auto / 1280 / 960 / 640 / 420 五档，设置 #frame 的 maxWidth，用于验证窄面板。
实现提示：真实实现可用 React/Vue 组件化拆分，但必须保留「页面纯函数返回结构 + 单一状态源 + 局部重绘优先」三条约束，否则一图秀的连续勾选体验会退化。
