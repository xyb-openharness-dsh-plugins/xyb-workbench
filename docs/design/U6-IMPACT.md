## 1. 内部矛盾：默认上传 vs 弹窗授权

(a)「默认上传」与「每次弹窗」在交互上互斥：

- 若**每次导入都弹窗** → 那不是「默认」，只是「推荐」，用户仍要主动点。
- 若**默认直接传** → 就没有弹窗（或只在首次弹一次）。

唯一自洽的解释（Chief 判断，待用户确认）：**首次使用弹一次授权弹窗，同意后即成为默认解析方式，之后不再反复问**。这是「弹窗授权」+「默认」唯一不自相矛盾的解读。

## 2. 交互方案选项（交用户点头，不替用户选）

| 方案 | 行为 | 后果 | 推荐 |
|---|---|---|---|
| **A 每次导入都问** | 每次导入弹窗确认是否上传云端 | 隐私最安全；但「默认」名不副实，体验碎；与 (a) 直接冲突 | 否 |
| **B 首次问一次 → 之后默认** | 首次弹授权弹窗，同意后成为默认，不再反复问 | 兼顾「默认」与「授权」；需持久化同意状态 + 可撤回；最贴合用户「a+弹窗授权」 | ✅ **推荐** |
| **C 按文件类型问（仅扫描件问）** | 数字 PDF 直接云端；扫描件才问是否 OCR 上传 | 折中；但默认路径仍是无弹窗上传，与「弹窗授权」弱关联 | 次选 |

**推荐 B**：首次授权弹窗明确告知「病历内容将发送至 mineru.net 云端解析」，同意后写持久化标志；设置页提供撤回入口（改回仅本地）。

## 3. 连带问题 1：precision 模式 token 谁提供

现文档：`RESOURCE-DEPENDENCIES.md` §9 #2 —— 用户自填（设置页有「打开 mineru.net/token 申请页」）。

改为默认上传后，**token 缺失会变成主路径阻塞**（没 token 没法传云端）。建议：

- **保留「用户自填」为 precision 模式前提**（项目方不出 token，成本与合规考量）。
- 但默认解析走 **pipeline 模式**（U7 已定：无幻觉、略低准），pipeline 可走项目侧/匿名配额或用户 token 二选一；**缺 token 时降级到「本地 pipeline 或手工录入」，不得因缺 token 卡死导入**。
- 设置页需明确：默认解析 = pipeline（无幻觉略低准）；precision 需用户 token；缺 token 时 precision 入口禁用并提示申请。

## 4. 连带问题 2：CLI 随包 vs 用户自装

现文档：`RESOURCE-DEPENDENCIES.md` §8 体积预算——CLI 随包可能是体积最大项（门槛 1），原「随包优先体验」。

改为默认云端后：**本地 CLI 不再是主路径必需**（云端负责图片/PDF→文本）。建议：

- 主路径不再依赖本地 CLI；CLI 降级为**离线/扫描件兜底**（对应 T12 本地 OCR 方向），可改为**用户自装可选**，体积预算释放。
- 若仍要离线能力，CLI 随包作为「离线模式」开关后的可选组件，而非默认依赖。

## 5. 隐私与合规影响（必须同步改，但先出方案）

(a) 默认上传 = 病历文本默认离开本机 → 直接冲突原原则「不假设用户同意上传病历」「宁可漏不可编、不出境」。

需补（落到文档时）：
- 首次弹窗文案**明确「病历内容将发送至 mineru.net 云端解析」**，而非模糊授权。
- 同意状态持久化 + 设置页可撤回（改回仅本地）。
- 明文告知数据出境（第三方）；与 `STORAGE-SPEC`「病历原件不进数据库、本地优先」需重新对齐——云端解析 ≠ 进数据库，但**出境事实成立**，须在隐私条款显式说明。
- 只传待解析的病历文件；解析结果回传后本地留存，不直接外发其他字段。
