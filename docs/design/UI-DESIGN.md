# 小胰宝工作台 · 界面设计提案

版本：0.4-design · 2026-10-13 · **供修改和确认，不代表生产实现或已安装**

配套：[需求与范围](SPEC-v0.4.md) · [看板规格](DASHBOARD-SPEC.md) · [匹配规格](MATCHING-SPEC.md) · [接入设计](INTEGRATION-DESIGN.md) · [交互原型](prototype-v2.html)

> v0.3 的界面稿（三 Tab：总览/病情资料/临床试验）与原型 `prototype.html` 保留为历史。本稿按 SPEC-v0.4 的「全局看板 + 一期两模块」重排导航与页面。

## 1. 设计决定

面向患者和照护家属。**默认首页是全局看板**：一屏看到病人在 8 个维度上的综合状态，再下钻到病情整理或临床匹配去处理。

推荐一个工作台、**七个一级 Tab**（看板 / 病情整理 / 病情一图秀 / 临床匹配 / 营养管理 / 心理支持 / 全程管理）。全部一期实现查看与记录；尚未实现的子页显示说明，不显示不可用的功能按钮。

**营养与心理为什么是一级**：营养（尤其胰腺外分泌功能不全）是独立于抗肿瘤治疗的干预线，有自己的评估与随访；心理支持涉及危机干预与临终议题，需要足够权重保证可被发现。放在二级会让最需要的人找不到。理由详见 [CARE-MANAGEMENT-SPEC §1.2](./CARE-MANAGEMENT-SPEC.md)。

**病情一图秀为什么单独占一个一级 Tab**：它是病友最想要的功能，但与看板的设计原则冲突——看板是「一屏速览、不做医学判断」，一图秀是「全病程细看、时间对齐天然引导因果联想」。两者服务不同认知任务，混在一起会同时损害两边。详见 [TIMELINE-SPEC.md](./TIMELINE-SPEC.md) §2。

采用 **业务整页 + 按需宿主会话（customFrame）**。浏览看板、整理资料、做匹配分析都不需要创建会话；只有主动使用 AI 时才创建或恢复宿主会话。

视觉方向是「**一张清楚的病人状态面板**」：品牌青绿取自官方 logo，近白纸面，**红黄绿三色表达状态**（用户要求，一目了然），灰虚线表达缺口。

与「监护仪式仪表盘」的区别不在于不用红色，而在于**红色只承载客观指标异常**：不铺大数字、不做风险评分、不出现工作台推断的「高危」。红绿灯负责指路，文字负责说清依据。特色元素仍是贯穿全页的**资料线索**：看板的每个状态、评估的每条结论、匹配的每条判定，都能点回原始材料或规则依据。

### 1.2 关怀型视觉符号

小胰宝以花朵和四叶草作为低强度的关怀性装饰，帮助页面保持温和、可亲近的气质。

| 符号 | 配色 | 推荐位置 | 动效 |
|---|---|---|---|
| 五色花 | 橙、粉、薄荷绿、浅蓝、暖黄 | 提醒开场、资料概况、心理支持 | 约 12 秒一圈的匀速旋转 |
| 七色花 | 五色花基础上加入淡紫、草绿 | 首页“现在可以做”、完成或阶段节点 | 约 15 秒一圈的匀速旋转 |
| 四叶草 | 薄荷绿 | 营养、照护、安宁疗护等较平静的区域 | 轻微左右摆动 |

实现规则：

- 花朵是装饰元素，使用 `aria-hidden="true"`，不承担状态、风险或医疗含义。
- 单个模块最多使用一枚主装饰；不和关键数字、警示图标竞争位置。
- 动效幅度小、节奏慢；进入页面可播放一次，持续动效只用于少量背景装饰。
- 必须尊重 `prefers-reduced-motion: reduce`，该模式下停止旋转、摆动与呼吸动效。
- 五色花与七色花保持低饱和色，不使用纯黑底，也不使用高对比闪烁效果。

### 1.3 指标卡片与动态效果

指标卡默认面展示最近一次已确认数值、单位、参考范围、相对前一次的上升/下降箭头和波动数值。箭头颜色只表达数值方向：上升为暖橙、下降为青绿、持平为灰；它们不表示病情好坏。

点击卡片使用约 480ms 的 3D 翻面展示最近五次以内的同指标趋势线；再次点击返回数值面。趋势线保留原始单位和时间顺序，并固定说明「曲线仅用于回顾已确认记录」。在 `prefers-reduced-motion: reduce` 下取消翻面、花朵旋转、摆动与呼吸动效，直接切换内容。

趋势图使用固定 320 × 62 的等比 SVG 画布，日期在 SVG 外以普通文字排列，避免宽卡片下非等比拉伸圆点、曲线或日期。营养管理顶部的体重、BMI、摄入能量和 PG-SGA 概览复用这套卡片；缺少连续记录时翻面明确显示“暂无趋势”，不生成模拟曲线。

一级 Tab 位于患者顶栏下方，水平展开，**Tab 文字前带序号**（`1 看板`、`2 病情整理`、`3 病情一图秀`、`4 临床匹配`、`5 营养管理`、`6 心理支持`、`7 全程管理`），便于口头指代。活动项使用深色文字、底部线和轻底色，不只靠颜色区分。二级导航放在页标题下方，各模块共用同一位置，避免导航跳动，**二级导航不加序号**。患者档案通过顶栏选择器和「编辑档案」进入，不占一级 Tab。数据位置、备份等属于资料库的轻入口，不能冒充宿主设置。

页头左侧放**官方 logo**。来源：`https://picgo-1302991947.cos.ap-guangzhou.myqcloud.com/images/xyb.png`（512×512 PNG）。

| 项 | 值 |
|---|---|
| 显示尺寸 | 30×30px（容器 34×34px 居中） |
| 处理 | 自动裁掉四周留白（原图内容区 314×420），保持比例 |
| 资源 | 项目内 `assets/xyb-logo.png`（128px 主档）、`assets/xyb-logo-original.png`（原档） |
| 原型实现 | 内联 base64 data URI（64px + 128px@2x 两档），**不引用外链**，保证单文件离线可用 |
| 可访问性 | `alt="小胰宝"` |

**不使用 SVG 复刻**：官方 logo 是 3D 渲染的拟物造型（青绿机器人 + 橙色爱心 + 天线），手绘 SVG 无法还原，会失真。必须使用官方位图。

**Tab 数量与窄容器**：七个 Tab 在 1280px 以下就会拥挤。规则是「一级 Tab 保持单行、文本不换行、必要时局部横向滚动并让焦点自动进入视区」，不折叠成菜单、不缩写文字。实测 1280px 下已接近临界，960px 及以下必须横向滚动。

**未实现子页规则**：尚未实现的子页显示名称、一句话说明与「即将开放」标签，**不渲染可点击但无功能的按钮**，不显示空图表。

## 3. 布局、尺寸与响应式

以**业务根容器宽度 W**判定布局，而非浏览器或 Electron 窗口宽度。宿主侧栏宽度由宿主管理，设计稿以 196px 示意，不作为实现常量。

```text
┌─ DSH 宿主 ─┬─ 小胰宝         患者 ▾          本机资料  AI 协助 ─┐
│ 模式与会话 │ 1看板 2病情整理 3一图秀 4临床匹配 5营养 6心理 7全程 │
│            │                                                │
│（仅示意）  │ 页面标题、说明                    本页主要动作    │
│            │ 次级导航 / 筛选                                 │
│            │ 主要内容（按实际宽度变为一列或两列）              │
└────────────┴────────────────────────────────────────────────┘
```

| 元素 | 建议尺寸 / 行为 |
|---|---|
| 业务根 | `min-width: 0; min-height: 0; flex: 1; position: relative; overflow: hidden`；不越过宿主容器 |
| 首个子节点 | 语义 `header`；48–56px 最小高，可换行；应用 `--dsh-frame-leading-clearance` 避让 macOS 窗口按钮和侧栏展开入口 |
| 一级 Tab | 48px 高，间隔 8px；始终可见，内容滚动在其下方 |
| 页面内边距 | W ≥ 1080：32px；760–1079：24px；520–759：20px；<520：16px |
| 最大内容宽 | 1280px 居中；宽屏不把段落拉成长行 |
| 卡片 | 16–24px 内边距、14px 圆角、1px 淡边框；组间 24px |
| 文本 | 系统中文字体 16px / 1.65；辅助文本 13–14px；页面标题 27–30px；数值使用等宽数字 |
| 操作 | 主要按钮最小高 42px；触摸或窄窗建议 44px；每个任务区域一个主操作 |
| 看板 W ≥ 1080 | 需关注项占左侧约 1.6fr；维度卡 2 列 × 4 行；卡最小宽 220px |
| 一图秀 W ≥ 1080 | 图表区 / 控制栏约 3.2:1；控制栏固定 244px；图表高 380–460px |
| 一图秀 760 ≤ W < 1080 | 控制栏移到图表上方，横向排列；图表高 320px |
| 一图秀 W < 760 | 单列；控制栏折叠为「筛选」抽屉；图表高 260px；时间轴可横向滚动 |
| 看板 760 ≤ W < 1080 | 需关注项占满宽；维度卡两列 |
| 看板 W < 760 | 单列；需关注项在最前；维度卡降为紧凑行式（标签 + 值 + 状态一行） |
| 报告核对 | 左右 1:1；单侧至少约 340px |
| 试验检索 | 列表 / 渠道栏约 2.7:1；W < 1080 时渠道状态移到列表上方 |
| 匹配分析 | 三档分组纵向排列；W ≥ 1080 时依据详情可并排 |
| AI 会话打开 | 宽布局可分出 360–420px 宿主会话；报告核对和 W < 1100 使用业务容器内覆盖面板或独立会话视图，关闭恢复原页面、滚动位置与编辑草稿 |

原型顶部的「画布宽度 / 宿主示意 / 场景」是评审工具，不进入产品。宿主侧栏只读示意，不复制可交互模式切换器。原型支持 1280/960/640/420px 业务容器，可单独收起宿主示意。

## 4. 视觉与可访问性

### 4.1 品牌色板（取自官方 logo）

官方 logo：`https://picgo-1302991947.cos.ap-guangzhou.myqcloud.com/images/xyb.png`（512×512 PNG，青绿机器人 + 橙色爱心）。色板从 logo 实际像素采样得出：

| Token | 值 | 来源 | 用途 |
|---|---|---|---|
| 墨绿 | `#1B3A34` | 加深自 logo 暗部 | 标题、深色正文 |
| **主青绿** | `#0F7C72` | logo 身体 `#05827c` 校准 | 主按钮、活动导航、链接 |
| 浅青绿 | `#95D0C7` | logo 头部高光 | 次级强调、图表辅助色 |
| 薄荷白 | `#F2F8F6` | 派生 | 页面背景 |
| 纸白 | `#FFFFFF` | — | 卡片、原件 |
| 石灰灰 | `#5A6E68` | — | 辅助说明（保证 ≥4.5:1 对比度） |
| **爱心橙** | `#D9612B` | logo 爱心 `#dc662f` 校准 | 唯一暖色强调，用于「重要但不报警」的标记 |

**颜色一致性锁定**：全站只用这一套。主色是青绿，**不引入第二个强调色**。橙色仅作为 logo 呼应色用于极少量标记（如「新」标签），不用于状态语义。

### 4.2 红绿灯状态色（用户要求）

在品牌青绿基础上定义语义色。**语义色与品牌色是两个系统，不混用**：青绿用于品牌与交互，红黄绿用于状态。

| 级别 | 主色 | 浅底 | 用途 |
|---|---|---|---|
| `good` 良好 | `#2E7D5B` | `#E8F5EE` | 有数据且未见异常 |
| `watch` 关注 | `#B8860B` | `#FFF6DC` | 需留意 |
| `alert` 警示 | `#C0392B` | `#FCEBE8` | 客观指标明确异常 |
| `unknown` 未评估 | `#7C8C84` | 白底 | 无数据，虚线边框 |
| `conflict` 冲突 | `#655472` | `#F1F0F6` | 记录互相矛盾 |

**三色必须同时满足**：

1. **文字标签并存**：颜色 + 文字（「良好/关注/警示/未评估/冲突」），不靠颜色单独表意。色盲用户与黑白打印可区分。
2. **图示形状区分**：`good`/`watch`/`alert`/`conflict` 用实心点，`unknown` 用**虚线空心**。即使全部转灰度，未评估仍可辨认。
3. **对比度达标**：浅底上的文字对比度 ≥4.5:1。`watch` 的黄底配深金文字（不是白字），`alert` 的红底配深红文字（不是白字）。

**红色的使用边界**：红色只表示「已确认的客观指标异常」，不表示工作台推断的风险，也不表示系统错误。全站不出现红色错误提示以外的第二种红色语义（前端常见冲突：红既表示错误又表示警告）。详见 [DASHBOARD-SPEC §1.2](./DASHBOARD-SPEC.md)。

### 4.2.1 视觉降噪原则（v2 修订）

用户反馈「维度状态下面的卡片很乱」「要素没有对齐」「画面整洁，颜色线条减少干扰」。据此定下四条硬规则：

| 规则 | 做法 |
|---|---|
| **颜色极简** | 卡片不再整块着色。颜色只用于 8px 状态点与级别文字，全屏着色面积 <2% |
| **线条极少** | 用 1px 分隔线替代卡片边框；一个 section 只有一个外框 |
| **层级靠留白与字重** | 不靠框、底色、装饰点制造层级 |
| **禁止重复动作** | 同一屏不出现多个同义链接（v1 有 7 个「查看详情」） |

**区块标题不加序号**。序号只保留在一级 Tab（`1`–`7`），用于口头指代。看板内 section 用 15px/640 小标题 + 浅灰副说明，不加 `01`/`02` 这类数字——视觉重量过大且无实际导航价值。

### 4.2.2 对齐基线

多列列表必须共用同一 `grid-template-columns`，保证每行每一列严格对齐：

```
状态点(8px) | 名称(108px) | 主值(1fr) | 级别(62px, 右对齐) | 折角(18px)
```

实测断言：所有行左缘坐标相同、级别列右缘坐标相同。禁止用 flex + 百分比宽度拼凑（会随内容长度漂移）。

### 4.5 可访问性

键盘顺序与视觉一致；Tab 切换支持方向键、Home、End；焦点使用 3px 清晰轮廓（用主青绿，不用系统蓝）；弹层限定焦点、Esc 关闭并把焦点送回发起按钮。加载和结果数量使用礼貌级状态播报；颜色不能是唯一信息载体；趋势图附同等信息的数据表。遵循减少动态效果偏好，默认没有自动动画（`MOTION_INTENSITY: 3`，仅 hover/active 过渡）。长标题自然折行，登记号可断行，输入框与按钮不被压成单字列。

**按钮对比度检查**：主按钮为深青绿底 + 白字（对比度 ≈5.8:1，达标）；次按钮为白底 + 深青绿字 + 1px 边框。不出现白底白字、也不出现浅色按钮压在浅色背景上无边框。

标题优先 `PingFang SC` / 系统中文；正文 `-apple-system`、`Microsoft YaHei`；登记号与数值 `SFMono-Regular` / `Consolas`。不加载外部字体。字号与排版承担层次，不把小字、细字当精致。

键盘顺序与视觉一致；Tab 切换支持方向键、Home、End；焦点使用 3px 清晰轮廓；弹层限定焦点、Esc 关闭并把焦点送回发起按钮。加载和结果数量使用礼貌级状态播报；错误不能只靠红色；趋势图附同等信息的数据表。遵循减少动态效果偏好，默认没有自动动画。长标题自然折行，登记号可断行，输入框与按钮不被压成单字列。

## 5. 页面与关键流程

### 看板

详细口径见 [DASHBOARD-SPEC.md](./DASHBOARD-SPEC.md)。界面要点：

顶部显示患者摘要（昵称、年龄、病种、资料更新至）与资料完整度（如「6/8 维」）。主体左侧为**需关注项**列表——跨维度聚合的所有 `attention` / `conflict` 条目，每条显示结论与依据（值、参考范围、记录日期），点击展开来源并可跳到对应资料。右侧为 8 个维度状态卡：体能、治疗情况、可匹配临床、营养、心理、并发症、毒性。

每个维度卡：标题 + 状态标签 + 核心值 + 「查看详情」跳转。无数据的卡使用虚线边框并显示「未评估」及补录入口，**不能显示为正常**。空状态下的「暂无需关注项」必须附说明「这不代表病情稳定，仅表示已记录内容中没有需关注项」。

首次无患者：两张并列入口「建立患者档案」「先浏览试验资料」，不显示空的 8 宫格。未授权目录不显示「已保存」或擅自创建文件夹。没有模型配置也能建立档案、收录资料、手动填写与查询本地试验；涉及 AI 的按钮说明需要选择可用模型，但不阻断其他业务。

### 资料库

主操作「添加资料」，次操作「资料位置」。支持列表展示文件名、材料日期、类型、解析/核对状态；状态为未解析、解析中、待核对、已核对、解析失败。每份材料可回原件，不以处理结果替代原始文件。批量操作仅作用于显式选中项；移除索引与删除原件应清楚区分，默认保留原件。

原型只演示新增一份虚构文件与状态，不弹真实目录选择器、不读取文件系统。产品导入完成要显示文件数、重复项、无法读取项和下一步。

### 报告核对

详细规格见 [REVIEW-SPEC.md](./REVIEW-SPEC.md)（多文档 + 多页面 + 页内异构）与 [EXTRACTION-SPEC.md](./EXTRACTION-SPEC.md) §4（抽取链路）。

**三种核对模式**，默认「按报告」，可切换：

| 模式 | 适用 |
|---|---|
| **按报告**（默认） | 顺序核对，左侧文件列表 + 原文/字段并排 |
| **按指标** | 同一指标跨多份报告横向比较 |
| **仅看待处理** | 收尾时隐藏已确认项 |

**布局**：三栏（文档来源 / 页面 / 候选字段）。

| 栏 | 内容 |
|---|---|
| 左：**文档来源 list** | 每份显示状态图标、文件名、**页数**、核对进度，以及**页级状态点**（`①②③`，标出 OCR 页与疑点页） |
| 中：**页面** | 页标题 + **解析方式**（本地提取 / MinerU 解析）+ 底部分页器；表格需**重建网格**后再展示 |
| 右：候选字段 | 采样日期、指标名、数值、单位、参考范围；每项标**页码**、原文片段、状态 |

**按页判定解析方式**（实测关键）：一个 6 页 PDF 里可能只有第 3、4 页是需要 OCR 的表格图片。按页分流后只上传这 2 页，既减少上传量也缩小隐私暴露面。单页失败不影响其他页。

**主操作「确认并下一项」固定在底部**，确认后自动跳到下一份待核对文件，不需要用户回列表点选。顶部显示跨文件累计进度（`已确认 7/12`）。

缺失用「未提取，请补充」，不能默认为 0 或正常。点击出处可在原件定位；无法定位时说明只能查看整页。核对界面需支持治疗记录、基因/病理、并发症三类字段，不只化验值。

只有用户保存确认的记录进入趋势、评估、汇总与匹配档案。编辑后的值保留「人工修订」、原始抽取值、来源、确认时间。

**冲突与重复**：

| 情况 | 处理 |
|---|---|
| 同日期同指标不同值 | 标为冲突，两条都显示，要求用户选择（不静默取一个） |
| 同文件重复导入 | 按 SHA256 去重，提示已收录 |
| 单位不一致 | 分开显示，不自动换算，标注「单位不同，未合并」 |

**不允许「一键确认全部」**——那会让核对形同虚设。批量操作只作用于当前筛选项，且必须显示影响多少条。

中断后再次进入，恢复到上次停下的文件与字段。解析失败的文件标失败并说明原因，其余照常核对。**核对不依赖模型**：无模型时链路退化为「解析文本 + 手工录入」，仍然可用。

### 指标趋势

详细规格见 [INDICATOR-CATALOG.md](./INDICATOR-CATALOG.md)。**按类别展示多指标**，不只单一 CA19-9。

**三层结构**：

| 层 | 内容 |
|---|---|
| 1 类别筛选 | 六类（肿瘤标志物/血常规/肝功能/肾功能/感染/代谢与营养），多选；显示各类项数与警示/关注计数 |
| 2 指标卡片 | 每项一张：名称 + 状态 + **大数字** + 单位 + 参考范围 + 迷你趋势线；点击展开**解读**与数据表 |
| 3 多指标对比 | **小倍数图**：每指标独立小图，共享时间轴，画参考范围底带与警戒线 |

**为什么用独立纵轴而不是归一化叠加**：各指标单位与数量级差异极大（CA19-9 上千、总胆红素个位数）。归一化会丢失原始数值，而医疗场景不能为了同图而丢绝对值。共享时间轴已能看出时间关联。

**危险值**：HGB 有 `warnLow: 100` / `dangerLow: 70`，PLT 有 50/20，NEU 有 0.5。达到警戒线时卡片标高一级，并在小图上画出警戒线。

**HGB 与消化道出血联动**：HGB 落入 70–99 时，展开解读额外提示「胰腺癌患者需注意消化道出血可能」，并在看板「并发症」维度关联。**只提示关联，不下诊断**。

**解读文案约束**：描述数值事实、列可能原因，不下结论；文案来自**随包模板**，不调用 AI 现场生成（医学表述需审核且需一致）。

**参考范围优先级**：报告自带 > 目录通用范围；两者不一致时**都显示不合并**；单位不同不换算。

### 病情评估

基于**已确认事实**生成结构化评估。区块：基本情况、诊断与病理、分子特征、治疗经过（含线数）、当前器官功能、体能状态、待补充项。

每条结论附来源引用，可点回资料或核对记录。没有资料的部分显示「暂无已确认资料」，不补写、不推断。AI 润色必须引用已有确认记录，不新增诊断、用药或疗效判断，可整体关闭。评估结果可重新生成，不覆盖用户编辑过的历史版本；原数据修改后提示可重新生成。

**治疗经过区块与临床匹配的入组档案是同一数据**，在此处编辑方案会同步反映到匹配模块。

### 病情汇总

展示当前患者、生成时间/版本、所含资料日期范围。默认收录已确认事实，分为基本信息、诊断资料、治疗记录、检查记录、准备问医生的问题、待补充项。每条事实保留出处；没有提供的信息明确为空，不由模型补写。

首期推荐可预览并导出 PDF（打印）或可编辑文档，具体格式以范围确认与接入可行为准。原型仅下载标为虚构演示的 `.txt` 内容，按钮明确写「下载演示文本」，不能据此宣称 PDF/Word 已实现。原型「问医生的问题」可在本次打开期间编辑。

### 病情一图秀

详细规格见 [TIMELINE-SPEC.md](./TIMELINE-SPEC.md)。界面要点：

**单页无二级 Tab**。上半为指标趋势图，下半为用药时间轴，两者**时间轴严格对齐**——这是该页的核心价值，让用户自己看出时间关联。

**默认打开即可用**：直接读当前患者本机数据，不需要先手工选三个 CSV。文件导入是迁移入口（按钮在页头，标注「导入旧数据」），不是日常操作。导出 CSV 随时可用，保证数据可携带。

左侧图表区：
- 多指标折线，同一指标不同单位**不连线**，分组展示
- 标注竖线（如「pectCT 情况 1」）贯穿上下两图，文本可避让重叠
- 关键点标记与变化率开关由用户控制
- 缺测留空断开，不插值
- 悬停显示日期、数值、单位、来源

下方用药时间轴：
- 每线方案一个色块，块内显示短标签与起止
- 图例即筛选器：点击可切换该方案的显示
- **只读**，提供「跳到病情整理编辑」链接（编辑集中在一处，避免误操作打断视觉连续性）

右侧控制栏：时间范围（年）、显示控制（关键点 / 变化率）、指标选择（搜索 + 复选）、生成图表按钮。

**必须常驻的说明**（不可省略）：图下方一行中性说明——「图表按记录时间排列。曲线升降不代表治疗有效或病情进展，请与医生一起解读。」这一条是因为时间对齐天然引导因果联想，而工作台不能下医学结论。

**空状态**：无已确认指标时显示「还没有可绘制的已确认指标」+ 跳转导入资料；只有一条记录时不给连线，显示为单点并说明。

### 入组档案

匹配分析的输入页，分组纵向排列。全部字段来自病情整理，本页**只做查看、补录与跳转**，不重复维护第二份数据。

| 分组 | 内容 | 界面要点 |
|---|---|---|
| **基因检测（分子特征）** | KRAS 分型、TP53、BRCA1/2、CDKN2A、SMAD4、ARID1A、PALB2、BRAF V600E、ATM、ERBB2/3、NTRK/NRG1/ALK/ROS1/RET/FGFR2 融合、MSI/dMMR、TMB | **卡片网格 + 背景色**：浅绿=有变异，浅灰=检测阴性，虚线白底=未检测 |
| **病理 / 免疫组化（IHC）** | EGFR、C-MET、TROP2、HER2、CLDN18.2、TF、PD-1/PD-L1、B7-H3、Nectin-4、pan-TRK、CDH17、MTAP、CEACAM5 + MSH2/6、MLH1、PMS2、Ki-67、P53 等 | **卡片网格 + 阳性强度背景色**：深绿/中绿/浅绿表示阳性强度，浅灰=阴性，虚线=未检测 |
| 并发症状态 | 主要并发症及状态（活动/既往/无/未知） | 未知不等于无，用 `unknown` 级别显示 |
| 治疗线数与方案 | 每线方案、药物、起止、疗效评价、终止原因 | 药物显示原名 + 标准化通用名；未归一标「名称待确认」 |

**基因与病理必须是两个独立分组**，不能合并成一张表：前者是 DNA/RNA 变异（可定量、对应靶向药），后者是蛋白表达（半定量、对应 ADC/单抗）。完整靶点清单与卡片状态定义见 [TARGET-PANEL-SPEC.md](./TARGET-PANEL-SPEC.md)。

**最关键的一条**：`检测阴性`（浅灰实底）与 `未检测`（虚线白底）必须视觉可分。把「没做过」显示成「阴性」，等于告诉用户这条路已经排除，而实际只是没人查过。

页顶显示档案完整度（如「9/12 项」），列出本次分析会用到但缺失的字段，提供补录入口，同时说明「缺失会让部分条件显示无法判定」。药物未归一、KRAS 分型未记录这两项必须显著提示，因为它们会直接导致对应规则无法判定。

治疗线数与病情评估的「治疗经过」是同一数据：在此编辑会同步到病情整理。基因/病理同理，在病情评估页显示只读摘要。

### 试验检索

**未建档、未联网、未配置模型都可检索随包快照。** 不要求先填写病历。用户可显式点击「使用当前档案条件」，只把已确认且适用于公开检索的字段映射到可见筛选，不自动发送整份病历。

| 条件 | 推荐规则 |
|---|---|
| 关键词 | 标题、干预名称、适应症、来源登记号；空值合法；输入后点检索或 Enter |
| 病种 | 首期胰腺癌相关，但保持「全部」与其他受快照支持病种；标注当前快照范围 |
| 地区 | 招募中心所在地；国家、省/城市分层；机构所在地不可靠时标「中心地区待核实」 |
| 招募状态 | 「全部」默认；「登记为招募中」明确这是快照记录，不能称实时在招；未知单列 |
| 治疗阶段 | 首期仅在源数据可靠结构化时做硬筛选；否则做关键词补充或标注「未记录」并默认保留，避免漏掉潜在相关资料 |
| 收藏 | 与当前患者关联；未选择患者时先选患者，查询本身不中断 |
| 排序 | 默认登记更新时间（缺失排后）或来源原顺序；不做「适合度」「命中率」或 AI 资格评分 |

结果卡包含来源、来源登记号、标题、病种/阶段摘要、地区/中心摘要、登记状态、登记更新时间、快照时间、详情和收藏。已做过匹配分析的试验可显示「已分析」标记，**但不能用匹配结果过滤掉未分析的试验**（见 MATCHING-SPEC §6）。相同试验跨来源仅在有明确同一身份依据时合并，保留所有来源；不确定时标可能重复，不能静默去重。来源原文与系统归一化字段分开。

结果上方显示本次检索的**渠道覆盖**：本次覆盖 N/M 个渠道、未参与渠道及原因、各渠道数据截至时间。未就绪渠道不能被显示成「没有试验」。

详情呈现来源记录、入排标准原文及关键缺失、机构与联系方式（源数据有则显示）、日期、更新提示、收藏备注，以及「分析入排条件」入口。生产版本有「查看官方登记」直达来源页；原型记录均为虚构，因此不提供假官方链接、不展示真实登记号。入口文案保持「相关试验资料」，不声称可报名、符合条件或推荐治疗。

**无结果不是没有临床机会。** 文案为「当前快照和筛选条件下未找到记录」，同时显示仍生效的条件、快照覆盖、不可用来源；给出清除筛选、保留未知信息、联网更新的操作。查询失败不能显示 0 条结果，保留上次结果并标明查询时间。

### 匹配分析

详细算法见 [MATCHING-SPEC.md](./MATCHING-SPEC.md)。界面要点：

顶部显示该试验的三档计数：**已满足 N 项 · 可能冲突 N 项 · 无法判定 N 项 · 待确认规则 N 项**。四类**始终独立列出**，不合并、不加总、不换算成百分比。

三档分组纵向排列，每组内是逐条规则：

```text
⚠️ 可能冲突（2）
   · 既往未接受伊立替康治疗
```

- 「可能冲突」用麦黄标识，附患者档案中的实际值与来源，让用户自己判断。
- 「无法判定」用虚线灰标识，明确说出缺什么字段并提供补录入口。

**文案禁止**：「符合入组」「适合」「推荐」「匹配度 X%」「高匹配」。试验之间**不按匹配度排序**，避免暗示推荐。

档案或规则在分析后变更时，页面标「档案已更新，建议重新评估」并提供重新分析入口，保留旧结果供对比，不静默重算。

### 收藏

与当前患者关联的试验收藏列表，含收藏时快照、手动备注、人工跟进状态（如「已致电中心」「等待回复」）。来源数据更新后显示「来源信息有更新」并提供「收藏时 / 当前」对比，**不自动重写旧快照、笔记或跟进状态**。某条记录在新快照中消失只表示本版本未收录，不等于试验取消。

### 渠道配置

见 [MATCHING-SPEC.md](./MATCHING-SPEC.md) §5。分「本地数据」与「在线来源」两组，每项显示：状态、记录数、数据覆盖时间、最后检查时间、失败原因。

| 状态 | 表达 |
|---|---|
| 就绪 | 实心圆点 + 记录数 + 覆盖时间 |
| 部分可用 | 标注哪部分缺失，结果会标「覆盖不完整」 |
| 未就绪 | 明确说明缺什么（运行组件 / 数据 / 配置），不显示成「0 条」 |
| 失败 | 显示阶段与原因，提供重试 |
| 已关闭 | 用户主动关闭，可重新启用 |

更新单独于检索运行：显示「正在检查 / 下载进度 / 校验中 / 更新完成或失败」，更新失败继续使用上一次完整快照。界面不暴露索引格式、接口密钥、适配器实现细节。原型更新明确标注「模拟」，不会联网、下载或安装数据。

### 营养管理

详细规格见 [CARE-MANAGEMENT-SPEC §2](./CARE-MANAGEMENT-SPEC.md)。要点：

**BMI 自动从身高体重派生**，不要求重复录入（与一图秀体重曲线同源）。顶部三张状态卡：BMI、体重变化、PG-SGA。体重变化取最近两次已确认记录计算，标出时间跨度。

能量区块只显示「记录的目标值」与「最近记录的实际摄入」的差距，**不给补充剂推荐、不给食谱**。胰酶替代区块在未记录时显示中性说明（胰腺外分泌功能不全可致脂肪泻与体重下降，可向医生了解），不主动建议。

PG-SGA 患者自评版（PG-SGA SF）可自行填写。得分按官方分界呈现，工作台不解释。

### 心理支持

详细规格见 [PSYCH-CARE-SPEC.md](./PSYCH-CARE-SPEC.md)。四个二级页：情绪自评 / 心理缓解 / 安宁疗护 / 哀伤管理。

**三个必须守住的点**：

1. **危机提示常驻**：四个子页底部都显示心理援助热线（12356、希望24热线 400-161-9995、紧急 120）。不可折叠、不可只在某一页出现。
2. **心理数据不发送给任何模型**。情绪自评得分与哀伤页浏览记录不进 AI 上下文。
3. **看板心理维度不用红绿灯**。全看板唯一例外：有数据显示「最近一次自评 日期」用中性色，无数据显示「未评估」。把情绪标成红色会造成二次伤害。

量表分级一律用官方分界，工作台不改写、不合并档位、不输出「你有中度焦虑」这类判断。PHQ-9 需提示其躯体症状条目与疾病症状重叠，得分偏高不一定代表抑郁。

外部资源（小馨宝、安宁疗护机构、哀伤支持机构）每条带**核实日期**，超 6 个月标「可能已变更」。措辞用「可供了解」，不用「推荐」。

### 全程管理

原「照护管理」更名收窄为 4 项：毒性管理 / 并发症管理 / 带管管理 / 血管通路管理。详细规格见 [CARE-MANAGEMENT-SPEC §3](./CARE-MANAGEMENT-SPEC.md)。

**列表页用 2 列大卡片**（一行 2 张，2×2）。每张卡五层信息：标题 + 状态徽标 / 一句话说明 / **关键指标大数字**（26px，淡灰底块）/ 覆盖范围 / 页脚（最近记录 + 关联线索）。状态色只用在左侧 3px 竖线和徽标底色上，卡片主体保持白底。窄容器改单列。

共性规则：

- 分级沿用红绿灯五级，红色仍只表示客观异常。
- **一期不做自动提醒推送**，带管与通路只显示「距上次维护 X 天」这类中性事实。
- 与看板对应维度同源；并发症状态同时是临床匹配的输入。
- ≥3 级毒性显示「建议尽快联系医生」，不给自行处理建议。

## 6. 患者与会话的一致性

当前患者在全页顶部固定可见，切换前若有未保存核对字段先提示保存/放弃/取消。切换后看板、资料、趋势、评估、汇总、入组档案、匹配结果、收藏与会话上下文一起切换。原型把核对结果、收藏和问题按患者分别保存在内存中，刷新即重置。

患者与工作台会话建立显式关联：优先恢复「当前患者 + 当前任务」的已关联会话，首次无会话也可完成本地操作。打开已有关联的历史会话时，优先恢复该会话绑定的患者与业务上下文；没有未保存编辑时同步切换，并明显显示「已恢复此会话关联的患者」。有未保存编辑时先提供保存/放弃/取消，解决前暂停会话切换与上下文发送，不能让患者业务面板与会话身份错配。恢复结果不能再被「最近使用患者」覆盖；没有映射的会话不猜测患者身份，而是明确选择后建立关联。

异步任务绑定发起时的 `patientId`、任务 ID、资料版本；用户切换后完成的解析保存到原患者草稿，只提示「另一档案有任务完成」，**不能把页面拉回旧档案、覆盖当前结果或把旧患者内容放进新会话**。保存采用版本校验，冲突时展示差异供选择。会话打开/关闭不清空本地表单。

发起在线模型操作前，用一处简短确认显示：「将把所选报告/已确认汇总发送给当前模型处理」。列出内容范围与接收模型，用户主动继续才发送；避免复杂授权层级和反复弹窗。换患者、换资料范围或换接收方后重新展示范围。原型只画宿主 conversation 占位，不实现聊天输入、模型调用或真正的发送。

匹配分析本身**不调用在线模型**（判定是确定性规则求值）；只有「抽取入排条件候选」这一步可能走模型，需按上述提示确认范围。

## 8. 原型评审与交付边界

用浏览器打开 [prototype-v2.html](prototype-v2.html)，不依赖服务、CDN、外部字体或网络。顶部「场景」可切换常规、首次使用、部分渠道不可用、无数据等状态。可操作患者切换、七个一级 Tab、看板维度卡下钻、病情整理二级任务、报告字段确认、一图秀的指标选择与年份筛选、入组档案的基因/病理卡片筛选、匹配分析三档展开、试验筛选/详情/收藏、渠道状态与模拟更新、营养管理、心理支持四个子页、全程管理四项、AI 会话占位及容器宽度。

v0.3 原型 [prototype.html](prototype.html) 保留，作为三 Tab 结构的历史对照，不再更新。

**一图秀在原型中的实现方式**：原型内联了一份自绘 SVG 折线图与时间轴（约 60 行），**不引入 ECharts**。原因是原型的目的是评审信息架构与交互，引入 1MB 的图表库会让单文件原型变重、且无助于判断设计是否成立。真实实现是否用 ECharts 见 [TIMELINE-SPEC.md](./TIMELINE-SPEC.md) §6。因此原型的图表**不能作为 ECharts 集成可行性的证据**。

所有患者、报告、试验、计数和日期为显著标注的虚构演示。输入只留在本次页面内存。不读取真实数据资产，不写用户目录，不向模型发送资料。宿主侧栏、文件导入、AI、更新状态是边界示意，不是 DSH 真实集成、临床检索效果或安装验收证据。匹配分析中的规则与判定为**演示用人工构造数据**，不代表真实试验的入排标准。

推荐评审顺序：看板能否一屏看懂病人状态 → **七个 Tab 是否过载** → 红绿灯是否一眼看懂且未评估明显区分 → 基因/病理卡片是否直观 → 匹配三档是否符合预期 → 心理支持的危机提示与措辞是否得体 → 营养只给差距不给处方是否合适 → 640/420px 与宿主收起是否清晰。

依据：[DSH 工作台开发规范 2026-10-09](https://dshdesktop.com/workbench/docs/development.md)，尤其 §4 界面边界、§5 工作台/会话/工作区。
