# v2 / v3 功能一致性审计

审计日期：2026-10-13  
比较对象：`prototype-v2.html` 与 `prototype-v3.html`

## 结论

当前 v3 **仍不能标记为与 v2 功能一致**。本轮已恢复一图秀的多选、时间范围、关键点、变化率和治疗轴联动；安宁疗护和哀伤管理；多患者切换；完整设置分区；三栏报告核对；营养体重趋势；以及 v2 的六类指标目录。剩余缺口集中在跨模块的数据联动、临床匹配详情、心理量表与全程管理的结构化详情。

## 子页差异

### 病情整理

| 子页 | v2 | v3 缺口 |
| --- | --- | --- |
| 资料库 | 文件清单、来源、状态和筛选 | 基础清单有，缺少完整索引状态与筛选结果联动 |
| 报告核对 | 逐页原文、候选字段、确认、跳过、跨页同指标比对 | 已有文档列、页面/原件列、解析与候选字段列、确认和比对入口；跳过后跳下一项与真实页码读取待接数据层 |
| 指标趋势 | 分类、状态卡、展开数据、独立纵轴小倍数图 | 已补肿瘤标志物、血常规、肝功能、肾功能、感染、代谢与营养六类目录；有数据项使用独立纵轴小倍数图，未记录项明确显示未记录 |
| 病情评估 | 病理、IHC、分子、治疗、营养与原始来源链接 | 当前只保留两条摘要 |
| 病情汇总 | 带来源的时间、检查、治疗、待办汇总 | 当前只有导出和预览入口 |

### 临床匹配

| 子页 | v2 | v3 缺口 |
| --- | --- | --- |
| 入组档案 | 完整度、基因、IHC、并发症、治疗线数、基础与体能 | 当前只有说明文字 |
| 试验检索 | 关键词、病种、地区、招募状态、覆盖提示、结果卡与来源状态 | 基础搜索页有；筛选和结果状态未完整对齐 |
| 匹配分析 | 已满足、可能冲突、无法判定、待确认规则四组和依据来源 | 当前只有三行摘要 |
| 收藏 | 快照、备注、跟进状态、来源更新比较 | 当前为空状态 |
| 渠道配置 | 本地和在线渠道的就绪、失败、重试、更新状态 | 当前只显示三项简略状态 |

### 营养管理

本轮已恢复体重趋势、能量链路、蛋白质范围、体重明细和 PEI 入口。仍需在数据层实现新增体重、摄入和 PEI 记录后，自动刷新趋势、差距和首页摘要。

### 心理支持

- 情绪自评需要恢复 DT、GAD-7、PHQ-9、HADS 的启动入口、量表分界、单量表趋势和历史表。
- 心理缓解需要恢复社区资源说明和六种日常缓解方法。
- 安宁疗护和哀伤管理内容已补回；服务筛选目前仅为原型控件，尚未连接本地资源筛选。
- 危机提示已经在所有心理子页常驻。

### 全程管理

v2 的核心是“管理卡 → 详情页 → 结构化记录”。v3 目前有毒性管理、并发症、带管管理、血管通路四个入口，但尚未恢复每项的当前状态、记录字段、历史列表和维护天数等信息。

## 跨页一致性缺口

1. **单一事实来源**：v2 让资料核对、病情评估、入组档案、趋势和一图秀读取同一确认数据；v3 多处仍使用独立演示数据。
2. **来源追溯**：v2 的指标、病理、分子和匹配规则可回到原始报告或数据渠道；v3 只有部分“查看来源”按钮。
3. **状态语义**：v2 区分“未检测”“阴性”“未记录”“无法判定”和“待确认”；v3 多处合并成普通提示。
4. **初始状态**：v2 对未建档或数据缺失提供明确页面；v3 尚未系统覆盖。
5. **本机导入导出**：v2 描述了导入、去重、错误行和导出行为；v3 目前仍为原型提示。

## 建议补齐顺序

1. 临床匹配：入组档案、规则分组分析、收藏和渠道状态。
2. 全程管理：管理卡、详情页、结构化记录与维护历史。
3. 心理支持：量表、趋势和完整缓解资源。
4. 病情评估、病情汇总与首页任务的跨页单一事实来源。
5. 接通真实本机资料、解析、设置检测、导入导出与无档案状态。

在以上项完成前，不应在设计文档或交付说明中写“v3 与 v2 功能一致”。
