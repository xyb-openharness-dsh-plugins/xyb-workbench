# V3 原型功能树与实现对照

本清单是小胰宝工作台的 UI 驱动开发基线。原型是高精度交互规格；页面导航、二级页面、弹层、字段、状态、主要操作和完成反馈均属于需要实现的功能。不能以“页面大致存在”替代逐项对齐。

## 开发原则：先盘点，再实现，再验收

1. 开发前逐个浏览 V3 原型中的顶层页面、二级页面、弹层/抽屉、交互入口和空/加载/成功/失败状态，形成可追踪的功能树和功能要素清单。
2. 先把原型要素映射到路由、页面组件、数据实体、服务 API 和验收项；没有既存清单时，必须根据原型补齐。
3. 按完整流程验收：用户从哪里进入、看见什么、执行什么动作、得到什么可视化结果/结论、如何保存并回顾。不得把二级页面合并成一个长页面而丢失其导航和上下文。
4. 允许因 Desktop 容器技术差异调整实现方式，但需保留信息层级、字段、操作、反馈和页面间关系；差异要记录在实现对照表并解释。
5. 每次周度前端调整，先更新本清单和原型映射，再改实现；对照检查不得只依赖源码测试，需检查实际 Desktop 页面。

## V3 页面与功能树

```text
小胰宝工作台
├─ 看板
│  ├─ 患者切换 / 患者档案管理
│  ├─ 8 维度病情变化：左侧变化、右侧提示和分析（非诊断）

│  ├─ 病情评估（病理/IHC、分子特征、记录来源）

│  ├─ PEI 记录及近期营养记录
│  └─ 给我建议 → 营养助手提示词和页面摘要
├─ 心理支持（二级页面必须分开展示）
│  ├─ 情绪自评/自主感受记录
│  ├─ 心理缓解（呼吸练习、照护者沟通）
│  ├─ 安宁疗护（机构和服务来源）
│  └─ 哀伤支持/家属支持
├─ 全程管理

│  ├─ 并发症
│  ├─ 带管管理
│  └─ 血管通路

├─ 收藏与回顾（新增统一回顾入口）
│  ├─ 收藏的临床试验及快照
│  ├─ Agent 建议任务和重要对话的原生会话入口
```

## 原型弹层/流程要素索引

原型的 `data-open` 交互至少覆盖：资料新增、文件选择、资料详情、时间轴详情/导入/配置/导出、分子检测档案、PEI 记录、病情汇总导出、工作台设置、心理记录、资源详情、照护记录、治疗日历、Agent 查询/页面建议、临床试验详情/订阅、营养制剂与配方参考。实现时逐项确认其打开入口、内容、关闭/返回、保存结果和错误状态。原型动态生成的项目弹层也纳入清单。

## 一致性验收规则

- 页面、二级页面和弹层需有明确入口和返回路径；仅把内容放入同一长页面不视为实现。
- 临床搜索不止展示列表；详情、来源/状态、收藏和发给 Agent 追问构成闭环。
- 每个 Agent 请求须保存页面、角色、提示词快照、创建时间和原生会话引用；工作台不伪造 Agent 结果。
- 所有导出文件有持久记录，可在「收藏与回顾」找到；本地文件路径应相对于数据根目录显示。
- 组件状态不得因其他卡片点击、页面重渲染或数据刷新意外丢失；卡片独立维护展开/翻转状态。
- 未实现/不可验证的项必须标为待办，不得用静态占位内容声称流程已打通。
